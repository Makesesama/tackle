# Changelog

Notable changes to Tackle are recorded here. This repository contains separate Mix projects under `packages/` and `apps/`; the entries below describe the repository as a whole. A version in a Mix project is not, by itself, a published package or a tagged release.

## Unreleased

### Added

- Added an MIT license and this changelog.
- `Tackle.Lib.Hook` callbacks other than `after_turn/2` receive the run's cancellation signal in their context as `:cancellation_signal`, so a slow hook can stop early; the loop does not keep it in the state's context (a host's own `:cancellation_signal` entry is left alone).
- Fixed `Tackle.Lib.Hook` skipping hook modules that were not loaded yet. It checked callbacks with `function_exported?/3`, which is false for an unloaded module, so in interactive mode (tests, `mix run`, IEx) a hook nothing had loaded before never ran. Releases load all modules up front and were not affected.
- The Elixir compile gate. `Tackle.Elixir.CompileGate` is a hook that compiles, in the project node, every Mix project whose Elixir sources a turn changes with `edit` or `write`: once before the first change, to record the existing diagnostics, and again when the model answers. Errors and warnings that were not there before (compared without line numbers) continue the turn with one message listing them like the compiler does, errors first, at most `max_rounds` times per turn; a project whose node cannot start or load it, or whose compile times out, is skipped. Every decision can be logged as a JSON line. The harness depends on `tackle_elixir`: `Tackle.Config` has a `:compile_gate` option (`Tackle.Elixir.CompileGate.Settings`), the gate is off by default, because it shares the project's build directory with the agent's own `mix` commands; `"compile_gate": true` or a `compile_gate` object (`enabled`, `max_rounds`, `timeout_seconds`, `warnings`) in `$TACKLE_HOME/config.json` turns it on for sessions built by `Tackle.Config.load/1`, logging to `$TACKLE_HOME/logs/compile_gate.jsonl`, and `false` turns it off. A project's `.tackle/config.json` can tune the gate or turn it off but not turn it on; `Tackle.Config.new/1` alone leaves it off. The CLI's Nix build includes the package and its broker sources.
- Added `packages/tackle_elixir` (`Tackle.Elixir.*`, `:tackle_elixir`), step 3 of `docs/PROJECT_NODE_PLAN.md`: Elixir project nodes. `Tackle.Elixir.ProjectNode` starts a broker (`priv/project_node/broker.exs`) through a `Tackle.Executor` with the project's own `elixir`, inside the jail when the session is jailed, and talks to it over the broker's standard input and output in frames checked by `Tackle.Elixir.ProjectNode.Protocol`. The broker starts one project node per Mix project, loads the project without compiling or starting it, and drives it over Erlang distribution that stays inside the executor: loopback only, no EPMD, project nodes that do not listen, and a cookie passed through the environment. `compile/3` returns the project's diagnostics as `Tackle.Elixir.Diagnostic` data (warnings of unchanged files included) and honours a timeout and a cancellation signal. `Tackle.Elixir.ProjectNodes` keeps one client per executor. Nothing in the harness uses it yet.
- Commands can read standard input. The exec protocol is now version 2 with an `{:input, id, binary}` request (an older exec-server is refused at the handshake), `Tackle.Exec.Client.input/3` writes to a running command (at most `:max_input`, 1 MiB by default, per call), and `Tackle.Executor` has an optional `input/3` callback, implemented by `Tackle.Executor.Local` and `Tackle.Executor.Jailed` (`Tackle.Executor.input/3` returns `{:error, :unsupported}` for executors without it). The exec-server writes input from a process per command, so a command that stops reading cannot stall it, and kills a command that leaves more than 16 MiB unread. Standard input is never closed. A command that exits while input is still being written loses its exit status and ends with `"command stopped reading its input; exit status unknown"`. This is the channel to the planned project node's broker (`docs/PROJECT_NODE_PLAN.md`).
- Hooks can gate the end of a turn. `Tackle.Lib.Hook` has a new optional callback, `before_turn_end/2`, which runs after the model's final answer when no incoming messages are queued. Returning `{:continue, messages}` or `{:continue, messages, context}` appends the messages as user messages and continues the same turn, so a check such as a compile gate can send its findings back for repair; `:ok`, `{:ok, context}`, and `{:error, reason}` behave as for the other callbacks. `Tackle.Lib.Hook.invoke_before_turn_end/3` runs the callback across hooks. Plugin hooks get it through the existing hook registration. See `docs/ELIXIR_INTEGRATION_RESEARCH.md` for why gates come before new tools.
- Added a new `apps/tackle_hub` (`Tackle.Hub.*` and `Tackle.HubWeb.*`, `:tackle_hub`), which reuses nothing of the app removed below, phase 1a of `docs/TACKLE_HUB_PLAN.md`: the skeleton of a pull request review app on Phoenix, Ash/AshPostgres, Oban, and Cloak, with a `GET /health` endpoint that checks the database, the Cloak vault (AES-GCM with key rotation; a ciphertext that fails authentication is an error, where Cloak 1.1 returns `{:ok, :error}`), Oban with the Lifeline plugin, the empty Ash domains, and production configuration from the environment. Development and tests use a PostgreSQL server on `localhost:5432` (or the `PG*` variables); without one, `apps/tackle_hub/scripts/db.sh` runs a local cluster on a Unix socket from the development shell's PostgreSQL. `AGENTS.md` now accepts Jason as a transitive dependency of the app's frameworks; our code still uses `JSON`.
- `apps/tackle_hub` receives GitHub webhooks (phase 2 of `docs/TACKLE_HUB_PLAN.md`). Ash resources for the GitHub App (`ForgeApp`, its private key and webhook and client secrets encrypted with AshCloak), installations, repositories with their review settings (validated against `Tackle.Review.Settings`), and review requests. `POST /webhooks/github` reads the raw body before any parsing, verifies `X-Hub-Signature-256` in constant time, and turns deliveries into forge-neutral `Tackle.Hub.Forge.Event`s: installation and repository events keep installations and repositories in step (new repositories take the installation's defaults), pull request events request automatic reviews by each repository's `auto_review`, draft, and fork settings, and `/tackle review [profile]` comments queue a job that checks the author's write access and the current head through the GitHub API (app JWTs and in-memory installation tokens, `Tackle.Hub.Forge.GitHub`) before requesting a review. One request per head; a new head skips pending requests for older ones. `Tackle.Hub.Release.configure_github_app/0` stores the App from the environment and secret files, and the NixOS module installs `tackle-hub-release` to run such commands with the service's environment; the VM test stores an App through it and delivers a signed webhook. Nothing runs review requests yet.
- Packaged `apps/tackle_hub` for NixOS (phase 1b): the flake builds its release as `packages.tackle-hub` from the generated `nix/tackle-hub-deps.nix`, with the gix_ex NIF built from `Cargo.lock` and every dependency compiled with the app's `config/ash.exs`. `nixosModules.tackle-hub` (`services.tackle-hub`) runs it as a dedicated user with a local PostgreSQL database over peer authentication, migrations before start, secrets from an environment file, no Erlang distribution, systemd hardening that leaves user namespaces to the later review jail, and a home directory kept apart from the state directory. A NixOS VM test (`checks.<linux>.tackle-hub-vm`) checks the service end to end, and Woodpecker runs the app's checks against a throwaway PostgreSQL cluster and builds the package.
- The CLI distribution now carries a version per build. Burrito re-uses its extracted OTP release whenever the application version is unchanged, so a rebuilt binary with `0.1.0` ran the previous payload and only `tackle maintenance uninstall` fixed it. `apps/tackle_cli/VERSION` now holds the release version and each build stamps it: `mix.exs` from the checkout, the Nix package from a hash of the CLI sources, the `nix/` recipe, the nixpkgs revision, and the target platform. `TACKLE_VERSION` (or `releaseVersion` for the Nix package) replaces the whole string, for a local `mix release` or a pinned release build.
- Added `packages/tackle_openrouter`, an OpenRouter provider adapter (`openrouter/<vendor>/<model>`) with streamed reasoning and `reasoning_details` replay, automatic Anthropic prompt caching, session-sticky routing, and reported billing cost. The CLI and web distributions bundle it.
- Projects can carry a `.tackle/config.json`, found like `.tackle/agents` (nearest ancestor of the working directory, up to the Git root) and read through the session executor. It layers over `$TACKLE_HOME/config.json` (objects merge recursively) and under `TACKLE_MODEL`/`TACKLE_THINKING`, and accepts every field except `providers` and `show_subagent_sidebar`, so a repository cannot point your credentials at its own endpoint. Both files accept a new `agents` object that sets subagent profiles' `model` and `thinking` by name (`Tackle.Config` `:agents`, applied by `Tackle.Coding`). `Tackle.ProjectFiles.nearest_project_file/3` finds the file; `ProjectFiles.git_root/2` and `ProjectFiles.same_dir?/2` (recognises `$TACKLE_HOME` through symlinks) are now shared by project config, skills discovery, and the CLI's MCP project layer instead of being copied.
- `config.json` accepts `provider_options`, adapter-keyed settings that the harness passes to adapters as the `:provider_options` LLM option (credential-like keys are rejected). The OpenRouter adapter reads per-model provider routing from it.
- The interactive CLI reports itself to [Herdr](https://herdr.dev) when it runs in a Herdr pane: `idle`/`working` state for Herdr's sidebar, notifications, and `herdr agent wait`, plus `tackle --resume <session>` so Herdr can reopen the session after a server restart. One-shot `tackle run "prompt"` and `tackle sdk` do not report.
- Jailed execution works in linked Git worktrees, such as Herdr's worktree workspaces. The exec-jail launcher (`nix/packages/jail-git.sh`) checks that the worktree's `.git` file and Git directory point at each other, then mounts the worktree's own Git directory read-write except its pointers, and the main checkout's `.git` read-only except `objects`, `refs`, `logs/refs`, `rr-cache`, and `reftable`, without the main checkout's files. Commits, merges, rebases, stashes, fetches, and pushes work; deleting or renaming refs, writing configuration, and `git gc` need the host. The writable directories are bound through checked file descriptors (`--bind-fd`), so a concurrently running jail of the main checkout cannot swap a symbolic link in while a worktree's jail starts. A worktree whose pointers do not match (a moved worktree, or a `.git` file aimed at another one) fails to launch; `git worktree repair` fixes a moved one.
- In every jailed checkout, `.git/worktrees` and an empty `.git/config.worktree`, created on the host when missing, are now read-only, so worktrees are created on the host and `git worktree add` fails in the jail. A workspace whose `.git` is a symbolic link, or neither a file nor a directory, is refused instead of mounted.
- The jail can give Git a commit identity. `tackle-cli-jail` and the exec-jail launcher accept `gitConfig` (`lib.generators.toGitINI` attributes), mounted read-only as Git's global configuration (`GIT_CONFIG_GLOBAL=/etc/tackle/gitconfig`) in the jail, whose private home otherwise left Git without `user.name`/`user.email`, so the agent could not commit.
- The flake exports a Home Manager module, `homeModules.default` (also `homeManagerModules.default`): `programs.tackle.enable` installs `tackle-cli-jail` on Linux (`tackle-cli` elsewhere), `programs.tackle.settings` writes `~/.tackle/config.json` as a regular 0600 file on activation, and `programs.tackle.git.name`/`email` set the jail's commit identity.

- Workflows report live progress. `Tackle.Workflow.run/3` accepts an `:on_event` callback (`Tackle.Workflow.Progress`) for runs started, child agent activity, observed outcomes, `tackle.parallel` batches, and logs; `Tackle.Workflow.Fanout.map/6` gained the observer hooks it needs. The `run_workflow` tool forwards these as `:workflow_progress` events (a host event type, emitted with `Tackle.Lib.Tool.progress/3`), and the CLI draws them as a live flow chart in the workflow's tool card, folding to a one-line chain when the workflow settles.
- Workflow progress covers `tackle.classify`. Each call reports `:classify_started` (label, model, questions) and `:classify_finished` (the answers the script receives, probabilities included, or the failure reason) through `Tackle.Workflow.Progress`; calls that raise report nothing. `tackle.classify` accepts a `label` option naming the call in progress views. The CLI draws each classification as a `◆` node in the workflow chart with its questions while asking and its answers once answered, and the one-line status output labels classifications. The narrator ignores them: a classification is not a delegated run.
- The requesting agent can choose a child's model per run. The `subagent` tool takes an optional `model` argument (`"provider/model"`), and workflows accept `tackle.spawn(profile, prompt, {model = ...})` and a `tackle.parallel` callback returning `profile, prompt, {model = ...}`. `Tackle.Runtime.request_agent/4` gained a `:model` option backed by a new optional `Tackle.Runtime.AgentBackend.select_model/2` callback; `Tackle.Runtime.RootBackend` resolves the model against the child's configured adapters and keeps the profile's thinking level. Backends without the callback (currently `Tackle.Phoenix.RuntimeBackend`) refuse such requests with `{:model_selection_unsupported, model}`. `Tackle.Workflow.Fanout` requests may carry per-item options as `{profile, prompt, opts}`.
- Background subagents can be cancelled by their parent. The new root-only `subagent_cancel` tool (`Tackle.Tools.SubagentCancel`) stops a run cooperatively, terminates it after a short grace period, and consumes it without queuing a completion notice; a run that already finished is collected instead. `Tackle.Coding` and the CLI distribution grant it with the other subagent tools. `Tackle.Runtime.cancel_run/3` (backed by `Tackle.Runtime.Request.cancel_owned/3`) exposes the owner-checked cancellation to hosts.
- Workflows can pursue goals over many rounds, a pattern taken from Codex's `/goal`. Every `tackle.await` and `tackle.parallel` outcome now carries `tokens`, `tool_calls`, and `failed_tool_calls`, counted by the new `Tackle.Workflow.Meter` from the run agent's own events, so scripts can check a run's claims against what it actually did. `Tackle.Workflow.run/3` accepts a `:token_budget` for all of one workflow's runs; `tackle.budget()` reports `used`, `limit`, and `remaining`, and once the budget is spent `tackle.spawn` raises and `tackle.parallel` reports the new `"budget_exhausted"` item status (runs in flight finish). The `run_workflow` tool takes an optional `token_budget` that can only lower the host's `:workflow_token_budget` context setting. The workflow skill guide gained a "Goal loops" section: a fixed objective, rounds that work from the current worktree and end with a status line, stop rules based on run facts, an independent completion audit, and `budget_limited` as the normal end of an open-ended goal. `Tackle.Workflow.Fanout` passes `{:budget_exhausted, reason}` refusals through and sets `run_id` on the outcomes it collects.
- Sessions can be archived, as in Codex. `Tackle.archive_session/2` and `Tackle.unarchive_session/2` (`Tackle.Session.Store.archive/2`, `unarchive/2`) move an inactive session's directory to and from `$TACKLE_HOME/sessions/archive/`, keeping its project directory; `Tackle.Session.Storage` gained `archive_root/1`, `move_session/3` (which takes the writer lock, so a session open in another process is refused), and an `archived: true` location option. The catalog indexes archived sessions with `archived: true` and listing excludes them unless the new `:archived` filter is `true` or `:all`. The CLI adds `tackle archive SESSION`, `tackle unarchive SESSION`, `tackle sessions --archived`, a `/archive` command that starts a new session and archives the previous one, and Ctrl+A/Tab archive actions in the `/resume` picker. `--resume` of an archived session reports how to restore it.
- Catalog entries carry `context_tokens`, an estimate of the session's model context (`Tackle.Session.Projection.context_tokens/1`: the latest assistant usage plus the later messages as `Tackle.Lib.ContextUsage.estimate_message/1` counts them, text at four characters per token and images at 1,600 tokens each; the system prompt and tools are not included). A summary sidecar written before this field reads as `nil`; since such sidecars also lack the journal's size and modification time, the catalog replays the session at startup instead, unless its journal is compressed, in which case it reports `nil` until the session commits again.
- The TUI asks before resuming a session last active more than an hour ago, when the provider's prompt cache has likely expired and the whole context is re-sent uncached. The prompt shows the session's age, message count, and estimated context size (loaded through the session inspector for older summaries), and an input-cost estimate when the session uses the current model and it has a price card; sessions under 10k estimated tokens resume directly (`Tackle.CLI.TUI.ResumeConfirm`).
- Idle session journals are stored compressed. `Tackle.compress_idle_sessions/1` (`Tackle.Session.Compression.compress_idle/1`) replaces journals untouched for seven days with a verified zstd copy, `session.dlog.zst` (OTP's built-in `:zstd`, about 3× smaller for typical sessions), and compresses idle `recovery/` copies; it skips sessions that are live or locked, runs at most every six hours (a marker in `sessions/catalog/`), and removes stale temporary files. Compression is transparent: read-only replay decompresses into a temporary file beside the journal, a writable owner restores the plain journal under the writer lock before opening it, the catalog indexes a compressed journal from its summary sidecar (brought up to date before compressing), and archive, fork, and `--resume` accept either form. The plain journal is authoritative when both exist, and every decompression is checked against the size recorded in the zstd frame, since zstd returns a truncated frame's partial output without an error. Replay and compression happen before the session's writer lock is taken, which then covers only the final swap. The zstd file primitives are `Tackle.Session.CompressedFile` (`available?/0`, `compress/1`, `replace/3`, `compress_file/1`, `restore/1`, `with_readable/2`, which gives replay a readable copy, and `read_copy?/1`), used by the reader, the journal, and the pass alike. The CLI starts a pass in the background when the TUI opens (`config :tackle_cli, compress_idle_sessions: false` disables it).
- Session deletion (`Tackle.Session.Storage.trash_session/2`) now takes the session's writer lock like archiving, so a session owned by another process is refused with `{:session_in_use, owner}` instead of being moved from under it. Lock conflicts with the current OS process (a brief background compression) are retried for up to two seconds by `acquire_lock/2`, `acquire_existing_lock/2` (resume), archiving, and deletion. `Storage.atomic_write/3` accepts `create_dir: false`, and `Storage.Lock.acquire/2` accepts `reclaim: false` to report a stale fallback lock instead of reclaiming it.
- Hardened `apps/tackle_hub` against resource exhaustion. The NixOS module's new `services.tackle-hub.limits` sets `MemoryMax` (default `4G`), `TasksMax` (default 2048), and optionally `CPUQuota` for the whole service, with `OOMPolicy=continue`. The exec-jail launcher accepts `limits` (`tmpfsSize`, `fileSize`, `oomScoreAdj`); the review jail sizes its private `/tmp`, home, and `/dev/shm` at 256 MiB each, caps written files at 256 MiB, and sets an OOM score of 1000 so the kernel kills jailed processes first. The CLI's jail is unchanged. `POST /webhooks/<forge>` now refuses bodies over 5 MB instead of 25 MB, by `Content-Length` before reading, and reads nothing while no forge app is configured. The review jail smoke test checks the limits, and the VM test checks the service's limits and runs the review jail's launcher as the service user to confirm the PostgreSQL socket, the environment file, the home directory, and host processes are out of reach. The app's README documents what the reverse proxy must do (forwarded headers, body size, rate limits).
- Fixed `services.tackle-hub` so reviews can start: the service's sandbox kept Bubblewrap from creating the review jail, which failed closed. The service now allows `AF_NETLINK` (Bubblewrap brings up the jail's loopback over netlink) and no longer sets `ProtectKernelTunables`/`ProtectKernelLogs` (their mounts over `/proc` make the kernel refuse the jail its own `/proc`); `SystemCallFilter=~syslog` keeps the latter's syscall ban. The exec-jail launcher gained `restrictSockets`, a seccomp filter (`nix/packages/jail-socket-filter.c`) that lets jailed code create Unix, IPv4, and IPv6 sockets only; the review jail uses it, so jailed code still has no netlink. The module asserts PostgreSQL 16 or later when it creates the database, and orders the service after `postgresql.service` on NixOS releases without `postgresql.target`. The VM test now starts review jails under the service's configured sandbox, with a probe and through the release's `Tackle.Hub.ReviewJail`, and the README shows a NixOS nginx configuration.
- The CLI's jail can pass chosen host environment variables to the agent's commands, such as `GH_TOKEN` for the `gh` CLI. `$TACKLE_HOME/config.json` accepts a CLI-only `jail` object whose `env` lists variable names (`{"jail": {"env": ["GH_TOKEN"]}}`); a project's `.tackle/config.json` cannot set it, so a cloned repository cannot ask for the user's secrets. `Tackle.CLI.Jail` reads it with `Tackle.Config.File.jail_env/1` when the jail starts and passes each named variable that is set in the CLI's environment to `Tackle.Executor.Jailed.new/2`'s new `:env` option, which adds them to every command (a command's own `:env` wins) and keeps the values out of `inspect` output. The launcher's environment is unchanged, so the values never appear in its command line.

### Removed

#### Agent library (`tackle_lib`)

These removals are breaking; each names what replaces it. The behaviour changes that came with them are under Changed.

- The application-wide LLM adapter. `config :tackle_lib, llm: Adapter`, `Tackle.Lib.LLM.adapter/0`, and the selection-less `Tackle.Lib.LLM.generate/2` and `stream/3` are gone, since every host already passed `llm:`. Every call goes through a `Tackle.Lib.LLM.Selection` (`Tackle.Lib.LLM.select/2`): `generate_with/3` and `stream_with/4` take only a selection, and `Tackle.Lib.run/3` and `continue/2` raise `ArgumentError` for a state without one (`Tackle.Lib.State.new/1` still builds one, for inspection and restoring). The state's `model` field and `new/1`'s `:model` option are gone too (passing `:model` raises); `Tackle.Lib.State.model/1` reads the selection's model, so a host that swaps `state.llm` has no copy to keep in sync.
- `Tackle.Lib.JSON` and `Tackle.Lib.JSON.Default`, with the never-used `config :tackle_lib, json: Adapter` setting: the library, the Anthropic, MCP, and SDK packages, and the CLI call Elixir's `JSON` module directly. `Tackle.Lib.Cache` is gone as well; no adapter read its `cache: true` option.
- The prompt renderer. A loop turn used only its response schema, resolved from the state's `:prompt_renderer` or, for every in-repo host, from the `:tackle_lib, :prompt_renderer` and `:prompt_renderer_opts` application environment read on every request; a renderer that returned a schema turned every final answer into an `:empty_response` and was sent on tool steps too. `Tackle.Lib.PromptRenderer`, `Tackle.Lib.PromptRenderer.NativeTools`, `Tackle.Lib.SystemPrompt.add_tools/3`, `add_response_format/2`, `tool_descriptions/2`, `response_format_section/1`, `response_schema/1`, and `version_id/1`, the `:prompt_renderer`/`:prompt_renderer_opts` fields of `Tackle.Lib.State` and options of `State.new/1` and `Tackle.Config.new/1` (with its `{:invalid_prompt_renderer, module}` error), and the CLI diagnostics' renderer line are gone. The loop reads no application environment and sends every request without a response schema; tools reach the model only as provider-native definitions. `Tackle.Lib.SystemPrompt` keeps `new/0`, `add_section/3`, `add_raw/2`, and `to_string/1`; structured output for direct calls stays with `Tackle.Lib.LLM.generate_with/3`.
- `Tackle.Lib.Snapshot` and the state's `snapshot` field. The snapshot copied configuration a turn cannot change (the loop never writes the selection, adapter options, system prompt, tool registry, hooks, or retry policy, and hooks can only change the context), and its `turn_id`, `captured_at`, `system_prompt_version_id`, and `tools_version_id` were never read outside its tests. The loop reads that configuration from the state it threads through the turn. The `:turn_id` run option of `run/3` and `continue/2` is gone (passing it raises like any unknown option; the harness session, `tackle_sdk`, and `tackle_hub` no longer pass it), `Tackle.Lib.Compaction.compact/3` lost its `:snapshot` option, and `Compaction.resolve/2` is `resolve/1`. Deterministic `:id_generator`s yield one id fewer per turn.
- Most of the `Tackle.Lib` facade, which is now `new/1`, `run/3`, `continue/2`, `last_answer/1`, and `navigate/3`. Instead of `messages/1`, `model_messages/1`, `usage/1`, `branch_usage/1`, `context_usage/1`, `tree/1`, `completed?/1`, `error?/1`, `error/1`, and `compact/2`, read `state.messages`, `state.tree`, `state.status`, and `state.error`, or call `Tackle.Lib.State.model_messages/1`, `State.usage/1`, `State.branch_usage/1`, `Tackle.Lib.ContextUsage.estimate/1`, and `Tackle.Lib.Compaction.compact(state, :manual, opts)`. The CLI's status line uses `ContextUsage.estimate/1`.
- Unused parts of the tool contract: `Tackle.Lib.Tool.execute_tool_call/3` (use `Tool.settle/3`), `Tool.find_tool/2`, `tool_name/1`, `definition_id/1`, `normalize_args/2`, `build_tool_description/1`, and `render_description/2`; the optional `description_metadata/0` callback with `Tool.description_metadata/1`; `Tool.Schema.validate!/2`, `normalize_schema/1`, and `definition/4`; `Tool.Content.text/1`; `Tool.Policy.unsupported_llm_opts/0` and `sanitize_llm_opts/1` (see `Tackle.Lib.LLM.request_opts/3` below); `Tool.Registry.get/2` (use `lookup/2`); and the `{:array, type}` schema type (use `{:list, type}`). Stale tool definition checks are gone, since no adapter sent a definition id: `Tool.Call`, tool definitions, and registry entries carry no id (registry entries have no `:id`), tool results and errors carry none in their `metadata` (now `%{}`), `Tool.Registry.resolve/2` only fails with `{:error, :unknown_tool}`, and `Tool.Error.stale_definition/1` and the `:stale_tool_definition` reason and telemetry outcome are removed. `Tool.Schema.JsonSchema.validate_output/2` and `validate/2` went with the `:jsv` dependency: nothing validated JSON Schema output (a map output schema, such as an MCP tool's, is opaque), so `JsonSchema` only projects keyword schemas (`to_json_schema/1`); a host validator in a `{validator, schema}` output schema still works. The undocumented `state.context.telemetry.adapter` hook, a module whose `with_context/2` wrapped each tool's execution, is gone; the `[:tackle, :tool, :execution]` events and the `telemetry.tool_names` allowlist stay.
- `confirm/2` of `Tackle.Lib.Interaction` and the CLI's implementation. Nothing called it, and the wrapper returned whatever an implementation returned despite promising never to imply consent. Implementations should drop their `confirm/2`.
- `Tackle.Lib.Integrations.Registry`. It had become a wrapper whose `new/1`, `entries/1`, and `lookup/2` called `Tackle.Lib.Tool.Registry`'s, and `Tackle.Anubis` was its only user. Use `Tackle.Lib.Tool.Registry` directly: `Tackle.Anubis.register_all/3` and the `:tools` option of `dispatch/4` take tool modules or a `%Tackle.Lib.Tool.Registry{}`.

#### Sessions (`packages/tackle`)

- `Tackle.Session.close/1`, with the `{:tackle_session_closed, session_id}` broadcast and the CLI's handler for it. Nothing outside its test called it; it promised `:ok` but returned `{:error, :storage_busy}` or a persistence error, and during a turn it wrote `session.closed` while the turn still ran and dropped the turn's outcome. Hosts stop the scope (`Tackle.stop_scope/1`) instead, which leaves an active turn to resume as interrupted. The runtime no longer writes `session.closed`, and `Tackle.Session.Journal.close_journal/1`, which only tests called, is removed with it. Journals that contain the event still load: the projection keeps its `closed_at` but no longer has a `:closed` status, which stuck to a session resumed after it, so a later clean turn still listed it as closed. Summaries that recorded `"closed"` read as `:clean`.
- The keyword start options of `Tackle.Session`. A session starts from one `{config, %Tackle.Runtime.AgentContext{}, %Tackle.Session.Spec{} | nil}` tuple, the context its backend received and its durable session, if any; `start_link/1` with a bare config, `start_link/2`, the custom `child_spec/1` with its `:id` and `:restart` options (the agent supervisors set both), `:name`, `:parent`, the fallback lookups of the scope's coordinator and work supervisor, and `Tackle.Runtime.RootBackend.session_opts/1` are gone. The session no longer merges the runtime context's `:event_callback` into the agent's context, since the loop puts the run's own callback into every tool's context.
- `Tackle.Session.Stats` and the `stats` field of `Tackle.Session.Snapshot`. Nothing read them (the CLI derives model info and the latest usage itself), and every snapshot ran `Tackle.Lib.ContextUsage.estimate/1` over the whole conversation to fill them. Read `snapshot.agent_state` with `Tackle.Lib.State.usage/1` and `ContextUsage.estimate/1`; usage events still carry priced usage, model metadata, and context pressure.
- `Tackle.Session.Spec.storage/1` (read the `storage` field) and `Tackle.Session.Loader.decode_messages/1`, which only a test called; a projection's tree holds its decoded messages (`Tackle.Lib.Tree.transcript/1`).
- `Tackle.resume_session/3`, which nothing called: resume by starting a scope whose `Tackle.Session.Spec` carries the `session_id`, as the CLI does. Also `Tackle.tree/1`, `Tackle.Runtime.tree/1`, the `:tree` agent-backend operation, and `Tackle.Session.tree/1`, which only tests called; read the tree from the snapshot's `agent_state.tree`.
- Unused parts of the session persistence API, which nothing outside their tests called. `Tackle.Session.Journal`: `summary/1`, `status/1` (read `Journal.projection/1`, whose `last_seq` it reported), `begin_turn/3` (`begin_turn/4` takes the turn id the session mints), and the by-session-id entry points `persist_message/3`, `persist_tool_started/2`, and `persist_compaction/2` (the persistence hook and the committer resolve the journal themselves). `Tackle.Session.Reader.item_count/1`. `Tackle.Session.Log.format_version/0`, `schema_version/0`, `event_versions/0` (read `Log.schema/0`'s `versions`), `terminal_events/0`, and `known_event?/1`. `Tackle.Session.Codec.validate!/1` and `valid_role?/1`; its undocumented `encode_usage/1`, `decode_usage/1`, `encode_datetime/1`, and `decode_datetime/1` are private. The `force:` option of `Tackle.Session.Storage.Lock.acquire/2`, which nothing passed; the location options given to `Storage.acquire_lock/2` and `acquire_existing_lock/2` no longer reach the lock at all. The options of `Tackle.Session.Projection.new/2`, now `new/1`: a projection's title, model, and branching come from the events folded into it, and it no longer reads a `"tree"` key that no journal header ever had. `Projection.preview/2` is private (summaries keep their `preview`). `Tackle.Session.Storage.checkpoint_path/2`, for replay checkpoints that are still only planned.
- `Tackle.Session.Persistence.tree_parent/2`, and the `:credential_store` option of `Tackle.Config.to_agent_state/2` and `Tackle.Session.Loader.load/3`. The persistence hook, the inbox, and the repair of interrupted tool calls append messages through `Tackle.Session.Durable.append_message/3`, which links each to its tree parent, and the session puts its credential store into its configuration's `llm_opts` once, where the agent state, reconfiguration, and title generation take it from.

#### Other removals

- The `:event_callback` field of `Tackle.Runtime.AgentContext`. A delegated request copied a one-argument `:event_callback` into its child's context, but no backend has read it since the session stopped merging it into the agent's context, every in-repo caller passes a two-argument callback (which was never copied), and a backend calling it would bypass the request, which forwards the child's events from `:subscribe` with their run and renews the child's inactivity timeout. Backends deliver events through `:subscribe`; the `:event_callback` option of `Tackle.Runtime.request_agent/4` is unchanged.
- Removed `apps/tackle_web`, the unmaintained Phoenix web app, with its Nix package, CI job, and the Tailwind/esbuild tooling only it needed. `packages/tackle_phoenix` stays. A future web surface will build on a GitHub review app instead.
- Removed the review benchmark runner (`apps/tackle_cli/bench/review_eval.exs`, `bench/review_eval/lib`) and `bench/review_repro.exs`; the benchmark cases stay. The last version is in Git history at `a32552d`.
- Removed the workflow deadline. `Tackle.Runtime.Limits` no longer has a `workflow_timeout` key (passing it now fails with `{:unknown_limits, [:workflow_timeout]}`), so workflows no longer stop after a default 10 minutes; they run until they finish or are cancelled. `Tackle.Workflow.run/3` keeps `:timeout` as an explicit host opt-in that now defaults to `:infinity`, and the `run_workflow` tool no longer takes a `timeout_ms` argument. Delegated runs keep their `run_timeout` inactivity window.
- Removed the host-defined workflow primitive from `packages/tackle_runtime`: `Tackle.Runtime.Workflow` (`init/handle_result/handle_failure/handle_cancelled`), `Tackle.Runtime.Workflow.Server`, `Tackle.Runtime.WorkflowRef`, `Runtime.start_workflow/4`, `Runtime.await_workflow/2`, the `WorkflowRef` clause of `Runtime.cancel/2`, `Registry.workflow/1`, `Registry.workflow_count/1`, `WorkflowRef` entries in `Runtime.Ref`, and the `workflow_count` key of `Runtime.scope_snapshot/1`. Also removed the unused `Runtime.request_many/3` and `Runtime.await_many/2` batch helpers and the `workflow_start` benchmark. These were breaking changes to `Tackle.Runtime`, which had no caller outside its own tests and benchmark.
- Scripted workflows in `packages/tackle_workflow` are now the only workflow engine. It drives the same delegated-run primitive, so scopes, limits, spawn depth, cancellation, and `workflow_timeout` are unaffected; hosts that need another trusted coordinator under a scope use `Runtime.start_work/2`, which is unchanged.

### Changed

The agent library (`packages/tackle_lib`) was reworked for a smaller, stricter core. The changes are grouped by area below, each described in its final state; most are breaking, and the APIs removed outright are listed under Removed.

#### Agent loop and state (`tackle_lib`)

- `Tackle.Lib.run/3` and `continue/2` (`Tackle.Lib.Loop`) validate their options and raise `ArgumentError` before the turn starts for an unknown option, a state without an LLM selection, a hook `Tackle.Lib.Hook.validate!/1` rejects (hooks can be replaced on a built state), or a concurrent tool policy without a `:tool_supervisor`. The `:event_context` option is renamed `:tool_context`: it is merged over `state.context` for tool execution only. The loop puts the run's `:event_callback` and the call's `:tool_call_id` into every tool's context itself, so `Tackle.Session` and `Tackle.Phoenix.Runner` no longer pass the callback twice, and the Runner no longer forwards an `:extra_hooks` option nothing read. The undocumented `:cancel_signal` alias of `:cancellation_signal` is gone.
- Every turn starts and ends the same way. `run/3` and `continue/2` both reset the per-turn fields (`Tackle.Lib.State.reset_turn/1`: iteration count, status, `error`, `error_reason`); `run/3` used to keep them, so a finite `max_iterations` shrank with every turn and a successful turn still reported the last failure. Both settle tool calls a previous turn left without results before the first request, and `continue/2` emits `:turn_start`. Every exit goes through one place: tool calls left unresolved by an error or cancellation get synthetic results (`Tackle.Lib.Messages.interrupted_results/3`), an error turn emits `:error`, `:status_change` (`:error`), and `:turn_end`, a cancelled one `:status_change`, `:turn_cancelled`, and `:turn_end`, and the `after_turn` hooks run last. A turn runs with the configuration of the state it started with, and the loop reads no application environment.
- `Tackle.Lib.State` keeps only what outlives a turn and is not derived. Its new `error_reason` field holds the structured reason of an error outcome next to the human-readable `error` (the provider's `Tackle.Lib.LLM.Error`, a hook's or gate's abort reason, `:max_iterations`, `:empty_response`, a durable commit failure, an incoming-messages failure), and the `:error` event reports it as `reason`. A provider failure's `error` reads "Failed to get response: " and the error's message instead of an inspected term. The `tools`, `model`, `last_compaction_id`, `pending_assistant_id`, `overflow_retries`, `snapshot`, `prompt_renderer`, `prompt_renderer_opts`, and `tree_committer` fields are gone (`tree_committer` became `committer`, see below): read `State.tools/1` (the registry's modules, in the order given), `State.model/1`, and `State.last_compaction/1` or `last_compaction_id/1` (the tree); the per-step bookkeeping lives with the running turn. `State.set_status/2` and `increment_iteration/1` are removed, and `set_error/3` and `set_cancelled/2` are internal. `State.new/1` raises `ArgumentError` for an invalid tool, hook, `:committer`, `:compaction`, or `:tree`, and for a `:model` option.
- The loop normalizes every chat response into `Tackle.Lib.LLM.Response` (`content`, `thinking`, `tool_calls` as `Tackle.Lib.Tool.Call` structs, `usage`, `stop_reason`, `model`, `provider`, `provider_state`, and the result's `data`) before hooks, events, or messages see it; `Tackle.Lib.Hook.after_prompt/3` receives that struct instead of the adapter's data map. A step keeps one response and emits one `:step_end` for it. A response with neither content nor tool calls is asked again once, as a retry with reason `:empty_response` (attempt 1 of 1, outside the transient retry budget); a second empty response in a row ends the turn with the error reason `:empty_response`. Such a response used to re-enter the loop without a bound, or became an invented placeholder or the raw thinking as the answer. Every response, an empty one included, emits its own `:usage` event exactly once: streamed usage is no longer counted twice, since the loop drops the adapter's usage events. `Tackle.Workflow.Meter` adds up these `:usage` events and ignores `:step_end`, so it counts re-asked responses too.
- Provider calls moved into the internal `Tackle.Lib.Loop.Provider`, with one retry loop (the internal `Tackle.Lib.ProviderGate` is `Tackle.Lib.Loop.Gate`, and tool execution runs through the internal `Tackle.Lib.Loop.Tools`). A `:before_provider_call` refusal is host policy and is no longer retried. When an overflow compaction committed a pass before a later pass failed, the request is retried with the smaller context instead of failing the turn, and a disabled compaction no longer announces a compaction retry.
- `Tackle.Lib.last_answer/1` returns the final answer the conversation ends with: the content of the last message when `Tackle.Lib.Message.final_answer?/1` holds for it, otherwise `nil`. It used to return the latest assistant message with content anywhere, so a message that also requested tools counted, and after a failed or cancelled turn an earlier turn's answer came back.

#### Tools and hooks (`tackle_lib`)

- A message's tool calls are always `Tackle.Lib.Tool.Call` structs, `[]` (not `nil`) without calls, so SDK `message_end` events carry `"tool_calls": []`. `Message.assistant/1` normalizes the calls it gets through `Tool.Call.normalize/1` (which accepts a `Call` as is) and raises `ArgumentError` on one that does not normalize or a `:tool_calls` that is not a list. The harness's session codec decodes stored calls into `Call` structs and refuses a stored call that does not normalize with `{:invalid_tool_call, call, reason}`; the stored format is unchanged. `Tackle.Lib.Messages`, `Tackle.Lib.Tree`, code review's `report_findings`/`report_verdict` collection (`Tackle.Review.Tools.ReportFindings.call_field/2` is removed), and the CLI's transcript, tree, and subagent views read only `Call` structs. `Messages.unresolved_tool_calls/1` returns the unresolved `Call` structs instead of `%{id, name}` maps, and the new `Messages.interrupted_results/3` builds the synthetic results for them, used by the loop and by the harness's resume repair; `Tool.Error.interrupted/3` takes the outcome (`:interrupted`, `:aborted`, `:cancelled`, or `:unknown`), and the transcript text is unchanged. A call without an id in foreign history gets one derived from its message's id (or a hash of the message), so ids stay distinct and stable across requests.
- Tool errors and arguments follow simpler, stricter rules. A tool's `{:error, message}` with a binary message is what the model sees (`"Error: " <> message`); any other reason gets a generic text and stays in the error's `message` and `details`. The optional `model_error/1` callback is removed with its implementations in `bash`, `review_changes`, `report_findings`, `report_verdict`, the subagent tools, and `run_workflow`; tools must not put secrets in error strings, and the `read`, `write`, `edit`, and `load_skill` errors now reach the model. Argument validation errors are shown too (`"Error: Invalid tool arguments: path: is required"`). A provider call whose arguments are not valid JSON or not an object no longer fails the turn: `Call.normalize/1` keeps it with empty `arguments` and the new `argument_error` (`:invalid_json` or `:not_an_object`), and it settles as an `:invalid_input` error the model can see, without running the tool or the `:before_tool_execution` gate; `""` or blank arguments are `%{}`. `""` is a value of a `:string` field (so `write` can write an empty file) and counts as absent for other types; `:string` fields accept numbers and booleans but reject lists and maps; `:float` fields return floats; `:map` fields decode JSON object strings themselves, `{:list, :map}` items included. `Tool.Schema.validate/2` returns `"must be an object"` for a value that is not a map, and a keyword output schema reports a non-map result, `nil` included, as `:invalid_output`. The new `Tool.Schema.validate_schema/1` checks types and options; the DSL runs it at compile time and `Tool.Registry.new/1` when a tool is registered, so unknown types or options raise, and `JsonSchema.to_json_schema/1` raises on an unknown type instead of advertising a string. Settlement replaces invalid UTF-8 in a binary result, `Tool.Content` text and text parts, and error messages with U+FFFD, since such text broke every later provider request. The MCP plugin keeps a server's `isError` text and JSON-RPC error message model-visible, returns other failures as `{:mcp_call_failed, reason}`, and rejects at discovery an input schema whose option values Tackle cannot register. `Tackle.Anubis.dispatch/4` answers MCP clients with the error's model-facing `content` instead of its host-facing `message`.
- `Tackle.Lib.Tool` is split by job: the DSL macros in `Tackle.Lib.Tool.DSL` (`use Tackle.Lib.Tool` is unchanged), the settlement pipeline in the internal `Tackle.Lib.Tool.Settle` behind `Tool.settle/3`, and error construction in `Tackle.Lib.Tool.Error` (`unknown_tool/1`, `invalid_input/2`, `invalid_output/2`, `failed/2`, `crashed/3`, `interrupted/3`), which defines the generic model-facing text once and makes every message valid UTF-8. A tool that raises, exits, or throws settles as `Tool.Error.crashed/3` under both tool policies (the sequential policy used to re-raise exits and throws and end the turn with calls left unresolved): its `message` reads `"Tool crashed: ..."` and its `details` are `{kind, reason}`; a result JSON cannot encode is `:invalid_output`.
- Tool definitions carry JSON Schema: `Tackle.Lib.Tool.definition/1` puts the JSON Schema object of a tool's parameters (string keys) in `:input_schema` (`t:Tackle.Lib.Tool.definition/0`) instead of a list of field maps with types such as `"array<string>"`. The Codex, Anthropic, Ollama, OpenRouter, and DeepSeek adapters send it as it is (a definition whose `input_schema` is not a map is `{:invalid_tool, name}`; Codex keeps `"strict": null` and DeepSeek `"strict": false`), and `tackle_sdk`'s `tools/list` takes `parameters` from it.
- The context the loop gives tools is documented in the `Tackle.Lib.Tool` moduledoc (`:event_callback`, `:tool_call_id`, `:cancellation_signal`), and tools report progress with the new `Tackle.Lib.Tool.progress/3`, which emits a `:tool_progress` event (`Tackle.Lib.Event.tool_progress/3`) or a host event type with the call's `tool_call_id`, and does nothing without a callback. `bash`, `review_changes`, `subagent`, and `run_workflow` use it; their payloads are unchanged.
- Tool registries keep registration order: `Tackle.Lib.Tool.Registry.definitions/1` returned definitions in map order, so providers saw another order than `State.tools/1`. The registry has `entries/1`, `lookup/2`, and `modules/1`. `Tackle.Anubis` builds its tools into a `Tool.Registry`, so it validates tool modules the same way and raises `ArgumentError` for a duplicate tool name, where the old integration registry overwrote the entry and listed the second module twice. One check says whether a module is a tool, the new `Tackle.Lib.Tool.tool?/1` and `missing_callbacks/1`, used by `Tool.Registry.new/1`, `Tackle.Config`, the plugin catalog, and `Tackle.Coding`'s root tools, which now must export all four required callbacks.
- Tool calls run through one pipeline for both tool policies. Concurrent batches (the internal `Tackle.Lib.Loop.Batch`, formerly `Tackle.Lib.Tool.Batch`) clean up after themselves: on cancellation the tools, which see it through their call's signal, get two seconds in total to stop (so `bash` can kill its process group), calls that settle in time keep their results, and only the rest are killed (they report no `:tool_execution_end` and get their interrupted `:tool_error` when the turn ends). Tool tasks no longer outlive the loop process: if it crashes or is killed, a watchdog per task cancels the call's signal with reason `:caller_down`, waits the same grace, and kills the task, and the harness session no longer kills its tool supervisor's children when a turn task dies. Every per-call cancellation record is deleted, also for killed calls. A tool task that cannot be started (the supervisor is down or at its `:max_children`) settles as a crashed tool error together with the calls after it, instead of crashing the loop.
- Hook modules are validated. `Tackle.Lib.State.new/1`, and every turn when it starts, raise `ArgumentError` for a `:hooks` entry that is not a loadable module exporting at least one hook callback (`Tackle.Lib.Hook.hook?/1`, `validate!/1`, which the plugin catalog uses too): a misspelled module used to skip every callback silently, safety gates included. `Hook.invoke/4` takes only its events (`t:Tackle.Lib.Hook.event/0`; `before_turn_end` has `invoke_before_turn_end/3`) with the matching arguments and raises `FunctionClauseError` otherwise. The `before_tool_call/3` docs say what the loop does: a hook can veto the call, which ends the turn, or update the context, but cannot change the call.

#### Events and telemetry (`tackle_lib`)

- `Tackle.Lib.Event` has one constructor per core event (`turn_start/2`, `turn_end/3`, `turn_cancelled/3`, `status_change/2`, `step_start/2`, `step_end/3`, `message_start/1`, `message_end/2`, `usage/2`, `error/3`, `tool_start/2`, `tool_progress/3`, `tool_execution_end/2`, `tool_end/2`, `tool_error/2`, `retry_scheduled/5`, `retry_start/2`, `retry_end/4`, `compaction_start/2`, `compaction_end/2`, `compaction_retry/3`), so each core type has one payload whose keys are always present (`nil` when they do not apply); the moduledoc and `packages/tackle_sdk/PROTOCOL.md` list them. `:error` always has `reason`; `:retry_end` always has `reason` and carries the pending assistant message id as its event `id`, like the other retry events; `:tool_execution_end` has `result`, `error`, and `reason`; a failed `:compaction_end` has every field of a completed one. An interrupted call's `:tool_error` has `details` and `metadata` like any other, and its `error` is the message without the transcript's `"Error: "` prefix. `Event.type` is a `t:Tackle.Lib.Event.core_type/0` or any host atom: `:subagent_started`, `:subagent_progress`, `:subagent_finished`, `:workflow_progress`, and `:narration` are host types, no longer listed in the library. `Event.normalize/2` keeps the value of `{type, value}` tuples (`{:text_delta, "hi"}` was an empty delta, and `{:usage, %Tackle.Lib.Usage{}}` was read as a map with a `type` key), and turns a map without a type, or with a string type it does not know (`"subagent_progress"` included), into a `:provider_event` that keeps the type as `provider_type`.
- `Tackle.Lib.Telemetry` spans follow the `:telemetry.span/3` conventions. `start/2` returns a `%Tackle.Lib.Telemetry{}` span (with its `telemetry_ref`) instead of a bare reference; `stop/3` and `exception/4` take the span (and `exception/4` the kind), add the `duration` and `monotonic_time` measurements themselves, and merge the start metadata into their own. `monotonic_duration/1` is gone. Exception events carry `kind` (`:error`, `:exit`, `:throw`), still never the raw reason or stacktrace, so tool-execution exception events carry `kind` instead of `error_type`. `Tackle.Phoenix.Runner` keeps the span as `turn_telemetry` (replacing `turn_telemetry_ref`, `turn_started_at`, and `turn_operation`), and its exception events carry `kind` and a bounded `error_type` (`:task_exit`, `:runner_terminated`, or `:call_failed`).

#### LLM boundary and provider adapters

- `Tackle.Lib.LLM` owns the result and request contract of every adapter call. `generate_with/3` and `stream_with/4` return `{:ok, %Tackle.Lib.LLM.Response{}}` (structured-output callers read the parsed object from its `data`) or `{:error, reason}`, and never raise. The result's `content`, `thinking`, and `tool_calls` may use string or atom keys; a malformed result (`{:ok, nil}`, a non-map `usage`, non-string `content`, invalid `tool_calls`, an unknown `stop_reason`, ...) or a return that is not `{:ok, _}`/`{:error, _}` is `{:error, %Tackle.Lib.LLM.Error{kind: :invalid_response}}` with the `:reason` and the spent `:usage` in its details, and an adapter that raises, throws, or exits is `{:error, %Tackle.Lib.LLM.Error{kind: :unknown}}`, which is not retried; either ends a loop turn with that error as `error_reason`. An adapter implements `generate/2`, `stream/3`, or both, and selection requires one of them. Keyword response schemas are converted to JSON Schema once in the library and map schemas get string keys, so the callbacks take `map() | nil`. The library sets the response's `provider` to the selected provider id, stamps `provider_state` with its `"provider"` and requested `"model"`, and drops every message's `provider_state` that another provider or model produced before calling the adapter. The response's usage is priced and is the call's usage of record: `stream_with/4` no longer prices `:usage` events or attaches `:context_usage` to them.
- Requests are built with `Tackle.Lib.LLM.request_opts/3`, whose module docs list the standard option keys: the keys that define a request always win, and host `llm_opts` override only the defaults, such as the loop's `temperature: 0.3`. Host options used to be appended, so adapters that read the first match ignored a host's temperature while adapters building a map took host values even for `:messages`. It drops the tool-selection options Tackle.Lib does not support (`:tool_choice`, `:parallel_tool_calls`, `:allowed_tools`, `:disallowed_tools`, `:tool_weights`, `:tool_policy`), so `Tackle.Lib.Tool.Policy` is only about execution mode; the compaction summarizer still sends its own `tool_choice: "none"`. `:native_tools`, `:strict_schema`, and `:max_output_tokens` are no longer sent (`:strict_schema` stays a Codex option defaulting to `false`). `Tackle.Session.Title`, `Tackle.Narrator`, and the review scorer build their requests with it, so session `llm_opts` no longer override their temperature, reasoning effort, token limit, tools, or tool choice, and they read the `Response`.
- `Tackle.Lib.LLM.Response` has a `stop_reason`: `:end`, `:max_tokens`, `:tool_calls`, `:content_filter`, or `nil` when the provider reports none. Adapters return it as the result's `:stop_reason`. Codex reports `:end` or `:tool_calls` for a completed response (an incomplete one stays an error) and documents that it never sends `:max_tokens`, which the ChatGPT Codex backend rejects; Anthropic maps its `stop_reason` (`pause_turn` is `nil`); OpenRouter, Ollama, and DeepSeek map `finish_reason` (`length` and filtered responses stay errors).
- Provider failures have one structured contract. Adapters return `{:error, %Tackle.Lib.LLM.Error{}}` for HTTP errors, transport failures, and errors reported inside a stream: an exception with a `kind` (`:transport`, `:timeout`, `:rate_limited`, `:overloaded`, `:server`, `:context_window_exceeded`, `:quota_exceeded`, `:auth`, `:invalid_request`, `:invalid_response`, or `:unknown`), the HTTP `status`, `retry_after_ms` from `Retry-After` (seconds or HTTP date) or `retry-after-ms`, a displayable `message`, and the raw `details`. `LLM.Error.from_response/3`, `from_transport/1`, `from_caught/2`, and `from_stream/1` classify failures for every adapter, with one list of context-overflow phrases matched only against error codes and messages (`overflow_message?/1`). `Tackle.Lib.Retry.retryable?/1` decides from the kind alone instead of running regular expressions over `inspect(reason)`, so transport failures (`:closed`, `:econnrefused`, `:nxdomain`, ...) and Anthropic's 529 are retried and any reason that is not an `LLM.Error` is not. `Retry.delay/3` takes the failure, waits at least its `retry_after_ms` (capped at `max_delay_ms`), and applies equal jitter unless `jitter?: false`. `LLM.context_window_exceeded?/1` recognizes only the struct, and `LLM.classify_error/1` is removed. `tackle_sdk` encodes exceptions without the `__exception__` marker.
- The Codex, Anthropic, OpenRouter, Ollama, and DeepSeek adapters report failures as `Tackle.Lib.LLM.Error`s, with response headers passed through so `Retry-After` works: `{:http_error, status, body}`, `{:request_failed, reason}`, `{:invalid_http_response, term}`, `{:provider_error, error}`, `:context_window_exceeded`, and the `:stream_ended_*` reasons are gone (a stream that ends early is a `:transport` error, SSE parse errors are `:invalid_response`), for `usage/1` and Ollama's `decide/2` too, and the unused `HTTP.error_body/1` helpers are removed. Codex converts its WebSocket failures (and a WebSocket upgrade's status and headers) before they leave the adapter, so the core no longer unwraps `{:websocket_transport_failed, phase, reason}`. An overflow reported inside a stream (Codex's `response.failed` with `context_length_exceeded`, error chunks in DeepSeek's streams) is compacted and retried like an HTTP one, and DeepSeek keeps the body of a streamed non-2xx response. The CLI's auth output renders an `LLM.Error` with its message and kind.
- The adapters implement only `stream/3`, which `Tackle.Lib.LLM` also calls for non-streaming requests, so their `generate/2` wrappers are gone (call `Tackle.Lib.LLM.generate_with/3`). They no longer convert response schemas, stamp `:provider` or `provider_state` (`stamp_provider/2` is removed), or check where `provider_state` came from; it holds only their payload (Codex `output`, Anthropic `content_blocks` with `oauth` and `stop_reason`, OpenRouter and Ollama `reasoning`/`reasoning_details`, DeepSeek `reasoning_content`). Anthropic still replays blocks only for the same auth mode, and since the library stamps the requested model, they are also replayed when the response names another model (Anthropic used to record the response's); `Tackle.Plugins.Anthropic.Convert.messages/2` lost its model and options arguments. `Tackle.Plugins.Catalog` accepts stream-only adapters.
- Every adapter accepts every `Tackle.Lib.Thinking` level and sends the nearest one the model supports, documenting its mapping: Codex follows its model catalog (`Tackle.Plugins.Codex.reasoning_levels/1`; `off` sends no reasoning options), Anthropic's adaptive models get the nearest `output_config.effort` (`Tackle.Plugins.Anthropic.effort_levels/1`) and budgeted models a budget for `max`, DeepSeek maps `minimal` to `low` and `medium` and `xhigh` to `high`, and OpenRouter and Ollama pass levels through. Values that are not levels fail with `{:invalid_reasoning_effort, value}`, now also on Codex. `Tackle.Lib.Thinking` gains `parse/1` and `nearest/2`; `put_llm_opts/2` no longer adds Codex's `reasoning_summary: "auto"` (the Codex adapter defaults to it), and `from_llm_opts/1` reads `:none` and values that are not levels as `"off"`.
- Adapters return canonical usage. `Tackle.Lib.Usage.normalize/2` reads only the struct's field names, as atom or string keys (what `Usage.to_map/1` and the session journal write, so stored sessions decode unchanged), keeps a map's `raw` field as `:raw`, and checks values; it no longer maps about thirty provider aliases (`prompt_tokens`, `cached_input_tokens`, `total_cost`, ...), which counted an OpenAI-style prompt count's cached tokens twice. The new `Usage.new/1` builds usage from an adapter's translation: the disjoint buckets, or an inclusive `:prompt_tokens` count from which it derives the uncached input; `:cost` is a number. The five adapters build `%Tackle.Lib.Usage{}` with the provider's report as `:raw` instead of string-keyed maps with a `"provider_usage"` key, and Anthropic reports no usage when the stream carried none. Adapters and test adapters returning usage maps must use the struct's field names. `Tackle.Lib.ModelInfo.estimate_cost/2` leaves usage with a provider-reported cost unchanged instead of attaching a price-card breakdown that disagreed with it.
- Adapters share their credential and setting lookups: `Tackle.Lib.CredentialStore.from_opts/1`, `CredentialStore.fetch/2` (which checks the store's return and reports failures as `{:credential_store_failed, reason}`, `:invalid_result` for a malformed one), and `Tackle.Lib.LLM.Provider.string_setting/3`, `put_base_url/2`, and `api_key/3`. Every adapter trims API keys and rejects ones an HTTP header cannot carry (`:invalid_api_key`), Ollama reports an invalid `"api_key_env"` like the others, Anthropic falls back to the environment when stored credentials hold neither an OAuth login nor a key, and an Anthropic 401 after the credentials were removed returns `{:missing_anthropic_credentials, id}`; its OAuth token retry reads `Retry-After` through `LLM.Error.retry_after_ms/2`. The harness uses the new `LLM.Provider.adapter_id/1` and `LLM.Provider.models/1` instead of the now private `Provider.call/3`, `instance_call/2`, and a copy of `validate_models/2`, so the plugin catalog reports a malformed model list with the provider's reason, such as `{:duplicate_model_id, provider_id, model}`. `Tackle.Lib.LLM.model_info/2` calls a bare adapter module that exports only `model_info/2` (such as Ollama) with empty settings instead of returning `{:ok, nil}`.

#### Compaction, conversation trees, and cancellation (`tackle_lib` and the harness)

- Every `Tackle.Lib.State` keeps a conversation tree; the library's linear mode is gone. `State.new/1` starts from an empty `Tackle.Lib.Tree`, and its `:tree` option takes only an existing tree (`true`, `false`, and `nil` raise). `state.messages` and `state.model_messages` (always a list) are cached derivations of the tree, written only by `State.add_message/2`, the new `State.put_tree/2` (used by restoration, navigation, and compaction), and the new `State.update_message/3` (with `Tree.update_message/3`), which replaces one settled message in place; `tackle_phoenix`'s runner uses it to attach event-only usage to the final answer. `Tackle.Lib.navigate/3` works on every state; branching is host policy, and the harness's `Tackle.Session` rejects navigation with `{:error, :tree_disabled}` for ephemeral sessions and durable ones that never enabled branching. A session snapshot's `agent_state.tree` is always a tree. Journals keep their format: `Tackle.Session.Journal` leaves out the implied `parent_id` of a session without branching and refuses any other with `{:error, :tree_disabled}`, and `Tackle.Session.Loader.load/3` installs the projection's tree for every session (its `:tree` option is gone), so existing `tree: false` journals load as single-branch trees. The CLI's tree screen opens for every session and explains a refused move.
- Compaction checkpoints are known by their tree entries, not their text: the new `State.last_compaction/1` (and `Tree.last_compaction/1`) returns the active branch's latest `Tackle.Lib.Compaction.Record`, `State.last_compaction_id/1` and `usage_segments/1` read the tree, `Compaction.Plan.select/2` and `Compaction.Input.fit/3` take a `:checkpoint_id`, and the CLI's `compacted` status and compaction cards read `last_compaction/1` (`Tackle.CLI.TUI.Compaction.completed/2` takes a record), so a user message that starts with `[[context-checkpoint]]` is no longer treated as a checkpoint. `Tackle.Lib.Compaction.Checkpoint` builds the checkpoint message (`message/2`), returns a record's summary text (`summary/1`), and applies a record to a message list (`apply_compaction/2`) for the live replacement and `Tree.model_context/2` alike; it replaces `Compaction.checkpoint_message/2`, `checkpoint?/1`, `checkpoint_body/1`, and `marker/0`.
- Compaction and navigation share one result shape and one durability seam. `Tackle.Lib.Compaction.compact/3` returns `{:ok, state, record}`, `{:error, reason, state}`, or `{:cancelled, reason, state}`, where `state` is the last committed state; `Compaction.nothing_to_do?/1` tells `:disabled`, `:no_context_window`, and `:nothing_to_compact` from failures, and the loop calls `compact/3` with `:pressure` before every request. Both commit through `Tackle.Lib.Committer` (`commit/2` with a `Compaction.Record` or a `Tree.Change` and `%{session_id: ..., context: ...}`), named by the state's `:committer`, which `State.new/1` validates; it replaces `Tackle.Lib.Compaction.Committer`, `Tackle.Lib.Tree.Committer`, the compaction config's `:committer`, and the state's `:tree_committer`. A committer that raises, throws, or exits fails with `{:durable_commit_failed, {:committer_crashed, committer, kind, reason}}`, keeping the exception or the thrown or exit value. The harness's `Tackle.Session.Compaction` and `Tackle.Session.Tree` are one `Tackle.Session.Committer`, with records encoded by `Tackle.Session.Codec.encode_compaction/1` and `decode_compaction/1`. A record names the tree entry it attaches to in `:parent_id`, its `:created_at` is a `DateTime`, and its `:details` have atom keys; the journal's `context.compacted` and `tree.navigated` data are unchanged, but an unknown or missing trigger is now a decode error instead of `:manual`. The compaction entry is appended to a copy of the tree before the durable commit, so a record the tree refuses is never journaled. `Tackle.Lib.navigate/3` delegates to `Tackle.Lib.Tree.Navigator.navigate/3` (the pure step is `Navigator.prepare/3`); its outcome is a `Tackle.Lib.Tree.Navigator.Outcome` (`change`, `draft`, `noop?`), and `Tree.Change` has no `session_id`. A navigation's committer and session always come from the state: the removed `:committer` option let any runtime caller navigate without journaling the change (`Tackle.Session` passed its caller's options through), and `:session_id` is gone too, so the only option is `:expected_revision`, any other raises, and `Tackle.Session.navigate/3` forwards only that one. Removed: `Tree.restore/2` (the session loader installs the replayed tree), `Tree.size/1`, `active_entry/1`, `last_answer/1`, `Tree.Entry.message/1` and `compaction/1`, and `Compaction.config/1` and `enabled?/1`.
- Compaction is configured more strictly. It is disabled only by a `nil` config: `Compaction.Config` has no `enabled?` (nor `put_committer/2`), `State.new(compaction: false)` raises, and the harness's `compaction: false` resolves to `nil`. `Compaction.Config.new/1` and `Policy.new/1` reject unknown options. The policy has one `summary_max_tokens` (8,192 by default, lowered to the model's output limit) instead of `summary_max_tokens` and `max_summary_tokens`. `Compaction.Request` has no `model`, `model_info`, or `prior_summary` (read the selection; the earlier checkpoint is sent once, as the first shadowed message), and `Compaction.Prompt.directive/1` no `:prior_summary` option. A summary uses the state's adapter options.
- Compaction no longer fails, loops, or overflows where it could make progress. `Tackle.Lib.Compaction.Summary` carries the response's `stop_reason`: only `:max_tokens` (or, without a stop reason, visible output reaching the cap) is `:truncated_summary`, where any summary whose output tokens reached the cap was, though Codex ignores the cap and counts reasoning as output; `:content_filter` fails as `:summary_content_filtered`. `Summarizer.LLM` asks for the `"minimal"` thinking level. A failed pressure compaction is not retried for the rest of the turn. A pass must make progress: a plan that would shadow only an earlier checkpoint, or a manual compaction of a conversation within the retention target, is `{:error, :nothing_to_compact}`, and a pressure compaction whose last pass does not land below the threshold is `{:error, :insufficient_reduction}` and not committed. `Compaction.Policy.resolve/3` takes `:fixed_tokens` (system prompt, tools, checkpoint framing) and the request's `:max_tokens`: the response reserve is that limit, or the model's output limit capped at the new `max_response_reserve` (32,768), so Codex models no longer compact at about half their window; the retention target stays at most half of the resolved `max_retained_tokens` (what can be kept below the threshold after a compaction), and a window without room for that is not used for pressure compaction. `Compaction.Plan` cuts only where no tool call waits for its result, never shadows only a checkpoint, and shadows a message too large to keep. The new `Tackle.Lib.Compaction.Input` shortens the largest shadowed messages, with a marker, when the summarization request would not fit the window (only where that makes them shorter), so an oversized tool result no longer makes the summarizer overflow. A custom summarizer's result other than `{:ok, %Summary{}}` or `{:error, reason}` fails with `{:invalid_summary_result, result}`, and one that throws or exits with `{:summarizer_failed, {kind, reason}}`.
- Manual compaction can be cancelled. `Tackle.Session` gives each `Tackle.compact/2` a cancellation signal, and `Tackle.cancel/1` on an idle agent and runtime branch cancellation cancel it; the call returns `{:error, {:cancelled, reason}}` (`:user_cancelled` from `Tackle.cancel/1`) and commits nothing. In the CLI, Esc cancels a manual compaction.
- `Tackle.Lib.Tree` keeps an index of each entry's children, so `Tree.children/2` no longer scans every entry. The new `Tree.resumable_ids/1` returns every safe continuation point in one walk, and `Tree.resumable?/2` uses sets; the CLI's tree view uses both, so opening a large tree is linear instead of quadratic or cubic.
- Cancellation fixes. `Tackle.Lib.Cancellation.cancel(signal, nil)` cancels with `:cancelled` (it stored `nil`, which read as not cancelled); the first reason wins, so a later `:session_closed` no longer hides `:user_cancelled`; and `Cancellation.delete/1` also deletes the per-call signals derived from the signal, so hosts no longer track cancelled call ids (`Tackle.Session` dropped its `cancelled_calls`). Custom `Tackle.Lib.Cancellation.Store`s must keep the first reason and delete derived `{signal_id, _}` records. `Tackle.SDK.Server` deletes each turn's signal when the turn ends. `Tackle.Runtime.CancellationStore`, a copy of `Tackle.Lib.Cancellation.Store.Ets`, is removed with the runtime application's boot-time switch of the `:tackle_lib` `:cancellation_store` setting, which gave signals created before and after the runtime started different stores.

#### Context and cache usage (`tackle_lib` and the CLI)

- `Tackle.Lib.ContextUsage.estimate_message/1` estimates what requests send: text parts like text, images at 1,600 tokens each, other parts by size (images a tool read were not counted); reasoning text and a tool call's raw provider form do not count, an assistant message with nothing to send counts nothing, and provider continuation state counts (the larger of it and the content it replays). `ContextUsage.since_checkpoint/1` splits newest-first messages at their latest usage checkpoint, and `Tackle.Session.Projection.context_tokens/1` uses it, so catalog `context_tokens` counts images too.
- The CLI's cache indicator (`CH`) no longer drops after a compaction, which it measured as a miss. `Tackle.Lib.Usage.cache_reuse/1` and `cache_reuse_rate/1` also take a list of sequences, measured separately and summed, and the new `Tackle.Lib.State.usage_segments/1` splits a conversation's usage at the compactions on its active path; the TUI measures each span, splitting the running turn at compactions it reports.

#### Messages and decisions (`tackle_lib`)

- `Tackle.Lib.Message` checks message ids: an explicit `:id` (now documented on `user/2` and `tool_result/4` too) or an `:id_generator` result that is not a non-empty string raises `ArgumentError`. Previously `id: 123` raised `CaseClauseError`, and `id: ""` or a generator returning a non-string was stored. The constructor options of `assistant/1` are documented.
- `Tackle.Lib.Decision.decide/3` is a boundary like `Tackle.Lib.LLM.generate_with/3` and never raises. An adapter that raises, throws, or exits returns `{:error, %Tackle.Lib.LLM.Error{kind: :unknown}}` (details: `:adapter`, `:kind`, `:reason`, `:stacktrace`), and every result is checked against the request's questions (new `Tackle.Lib.Decision.Result.validate/2` and `Tackle.Lib.Decision.Answer.validate/2`): exactly one answer per question, of its type, with a `choice` among the options, a `noul` in `0..1`, a `score` within the scale, numeric probabilities and confidence in `0..1` keyed by option, `"true"`/`"false"`, or level, a string or `nil` model, and map or `nil` usage. A result that does not fit, or a return other than `{:ok, %Result{}}`/`{:error, _}`, is `{:error, %Tackle.Lib.LLM.Error{kind: :invalid_response}}` with the `:reason` and the spent `:usage` in its details; it replaces `{:invalid_decision_result, adapter, other}`. Previously junk answers reached hosts: the watchdog crashed on `answers: nil` and treated a string probability as above any threshold. The request-building `Decision.decide/4` is now `Decision.ask/4` (`opts` optional), so `decide/3` always takes a prebuilt request. `Answer`'s `score` is documented as a number from `0` to the number of levels minus one, fractional when an adapter reports the probability-weighted average of the levels (as Ollama does). With the boundary in the library, `Tackle.Workflow.Decisions.decide/3` no longer rescues adapter crashes (its `{:adapter_failed, _}` errors are gone), `tackle.classify` no longer re-checks answer types and still counts the tokens of an unusable answer from the error's usage, the watchdog drops its handling of missing verdicts and malformed results, and the Ollama adapter no longer re-validates the request and model; it translates its wire answers and reports a body that is not JSON, lacks `answers`, or holds an answer of unknown type as an `:invalid_response` `Tackle.Lib.LLM.Error` instead of `{:invalid_decision_response, _}`.

#### Sessions (`packages/tackle`)

- `Tackle.Session` keeps the decisions and delegates the pieces to helpers, listed in its module docs: `Tackle.Session.Turn` (the active turn, with an explicit starting, running, or settling status), `Tackle.Session.Inbox` (below), `Tackle.Session.Durable`, `Tackle.Session.Events` (below), and `Tackle.Session.Title`. `Durable` holds everything the session writes to or rebuilds from its journal: it opens the session, reading the journal's projection once where the session read it twice, rebuilds it after a crashed turn the same way, begins, settles, and abandons turns, records configuration changes, and provides the loop's provider and tool gates. `Title` keeps one title state (untitled, pending, titled, or failed); a session process still tries to title itself only once. Turns with and without a journal start through one path.
- Resuming a durable session restores the recorded selection, the pair of model and thinking level, exactly. Resume after `/model` on a session that never set a thinking level failed with `:configuration_required` (the journal records the unset level as `nil`, which the configuration's model and thinking update refused), a level set on the configured model was ignored, and with `override_config: true` a change of only the thinking level was not recorded. `Tackle.Session.Loader.load/3` returns the resolved `Tackle.Config` as `:config` (its `resolve_config/3` is private), and the session keeps it: a resumed session used to keep the launch configuration, so the next `reconfigure/2` silently switched back to the launch model and journaled it, and titles were generated with the launch model.
- A crashed turn no longer leaves a durable session's memory behind its journal. The session settled with the pre-turn state although the persistence hook had journaled the turn's messages, so without branching every later turn failed with `:tree_disabled`, with branching the next prompt silently started a new branch, and messages added during the turn were lost. After `turn.crashed` it now rebuilds the state from the journal's projection as resume does, repairing tool calls the crash left without results; a session without a journal keeps the pre-turn state.
- A turn whose start fails after `turn.started` is written (its queued messages cannot be journaled, or its task cannot be started) is settled with `turn.crashed` before the session goes idle, and the session stops if that write fails. The journal kept the turn active, so every later turn failed with `:turn_in_progress`, and an inbox-started turn failed silently; it now reports `:tackle_turn_failed`. A session without a journal emptied its inbox before starting the turn's task, so a task that failed to start lost the queued messages; they now leave the inbox only once the task runs.
- A slow disk pauses a session during an append as it does during a sync, instead of stopping it. `Tackle.Session.Journal.Deadline` gave only a live `:sync` the soft pause; an append past the journal deadline killed the journal and its scope, with `journal-failure.json` reporting `"stage":"append"`. Yet `:disk_log.log/2` waits behind the log's own blocking cache write, and since commits are written behind most of them never sync, so under writeback pressure the append is where a session waits. `:append` and `:append_header` now pause like `:sync` (storage `:delayed`, the request kept in flight and never retried) and log a payload-free warning per pause, `Session journal storage is slow; pausing`, with the operation, stage, sequence, and elapsed time. Stalls in stages that do not wait for the disk (validation, projection, the catalog update, an owner that stops responding), opening, and cleanup still stop the owner, and work after a resumed append gets a fresh hard deadline.
- Cancelling a turn stops the agent. A root session started a new turn with whatever was still queued as soon as a cancelled turn settled, since its inbox woke after every outcome, so Esc with queued messages did not stop it, and a second cancel left those messages in the conversation unanswered. Now the user's queued messages are handed back unsent in a new subscriber message, `{:tackle_input_returned, session_id, turn_id, messages}`, sent just before the turn's `:tackle_turn_finished`; other agents' messages and background notices stay queued for the next turn, and the session starts no turn for them until new input arrives (`Tackle.Session.Inbox.hand_back/1`). The CLI puts the returned messages back into the composer, oldest first and with their paste labels, above any draft being typed, as pi and Codex do.
- A submit or agent message for the active turn is queued even while the turn's begin or terminal event is being written or storage is delayed, since queueing writes nothing; it was refused with `:storage_busy`.
- A delegated session (the runtime's `:ephemeral` lifetime) no longer drops input it acknowledged after the loop last took queued messages, such as a `tell`, submit, or background completion arriving while `before_turn_end` hooks like the compile gate ran: after a successful turn it continues with that input before delivering the one terminal outcome, the last turn's. Error and cancelled outcomes are delivered at once, and queued input is dropped with the session; a continuation that cannot start is a `:runtime_error` with `{:continuation_failed, reason}`.
- A manual compaction's progress is a `{:tackle_event, session_id, nil, event}` like other events outside a turn, where it was `{:tackle_compaction, session_id, event}`; the CLI handles the new shape. It reaches the session's subscribers at the time of the event, like turn events: the compaction task sends it to the session, which broadcasts it. It was sent from the task to the subscribers of the moment `compact/2` was called, so processes that had unsubscribed still got it and new subscribers missed it. `Tackle.Session.Events` holds a session's subscribers and documents every message they receive.
- `Tackle.Session.cancel/2` takes the cancellation reason (`:user_cancelled` by default, which `Tackle.cancel/1` keeps), and `Tackle.Runtime.RootBackend` passes the runtime's: a delegated run cancelled by its owner, its request's termination, or a timeout records that reason, where every cancelled child recorded `:user_cancelled`.
- `Tackle.Session` ignores (and logs at debug level, by tag only) a message it does not expect, such as another session's `{:tackle_storage, ...}` notice. It raised `FunctionClauseError`, and since the root session runs under `max_restarts: 0`, a stray message took the whole root scope down.
- A durable session's agent context no longer carries `:session_owner` (the session's pid) or `:journal_required`; the loop merges the agent context into every tool's context, so tools saw both. `Tackle.Session.Persistence`, which `Tackle.Session.Durable` installs only in durable sessions, always fails closed with `{:journal_unavailable, :not_found}` when the session's journal is gone (without `:journal_required` it did nothing), and tells the session about appended user messages through `Tackle.Runtime.session_pid/1` for the context's `:runtime` agent reference.
- `Tackle.Session.Store` fixes: `fork/2` refuses a `:seq` that is not one of the parent's commit sequence numbers (negative, past the end, or not an integer) with `{:error, {:invalid_fork_seq, seq}}` instead of forking at it; it closes the child's log when writing it fails, where the log stayed open, and returns a failed close as `{:error, {:journal_close_failed, reason}}` instead of raising; and `summary/2` reads the journal when the catalog is not running instead of exiting.
- `Tackle.Session.inbox/1` returns one entry type, `Tackle.Runtime.Envelope`: user input queued during a turn is a `:message` envelope with `from: :user`, where it was a `%{from: :user, message: ...}` map, and `Envelope`'s `from` type admits `:user` (`Envelope.new/4` still never builds one, so a delivered envelope cannot pass as the user). The inbox, its capacity limits, and its delivery rules are the new pure `Tackle.Session.Inbox`; a delivered envelope is validated once.
- Automatic session titles come only from what the user wrote: a turn's input and the user's queued messages. Any user-role message the persistence hook appended could start the title, so an untitled session could be titled from an agent message (`Message from agent ...`), a background completion notice, or hook feedback such as the compile gate's. A queued user message that starts the next turn, which the session journals itself, now titles the session too.
- The session journal refuses a write it cannot record without writing anything or stopping, and keeps one rule for errors (in `Tackle.Session.Journal`'s module docs). A commit is now folded into the projection before it is appended: one that does not fold (a duplicate entry id, an unknown parent or navigation target, an undecodable compaction) was appended first and then crashed the owner, whose cleanup synced it, so the session could never be read, resumed, or indexed again; it is now refused with `{:error, {:invalid_commit, reason}}`. Invalid messages, tool calls, and settlements, a branch without branching, and a write without an active turn are refused the same way and leave the journal usable (an invalid message stopped the owner and the durable scope, with the breaking reply `{:error, {:journal_failure, {:invalid_message, reason}}}`, which is now `{:error, {:invalid_message, reason}}`); a failure once bytes may have been written (append, sync, lost lock, a `:disk_log` error notification) still stops it. The persistence hook fails a turn whose message the journal refuses with `{:message_not_journaled, reason}` (breaking for hosts matching the hook's error), and the session rebuilds its state from the journal after `turn.errored`, as after a crash, so memory never holds a message the journal does not.
- `Tackle.Session.Journal.settle_turn/3` settles only the active turn or, in a journal opened with an interrupted turn, that turn, and refuses any other with `{:error, :turn_mismatch}`. It used the active turn's id whatever the caller named, so settling another turn ended the active one, settling twice wrote a second terminal event, and settling a turn that never started invented one.
- `session.configuration_changed` records the normalized thinking level (`Tackle.Lib.Thinking.from_llm_opts/1`, `"off"` when none is set), as `session.created` does. It recorded the raw `:reasoning_effort` option, `nil` when unset, and a provider-specific value that is not plain data stopped the journal and the durable scope. Journals with the old values still load.
- A journal owner no longer stops when it waits for a writer lock this OS process holds briefly (background compression at CLI startup racing a resume, or moving a session to the archive or trash). Every failed `flock` attempt left the lock process's exit in the journal's mailbox, and the journal, which traps exits, stopped normally on it after starting, taking the scope down without a diagnostic. A lock process that ended now leaves no exit signal behind (`Tackle.Session.Storage.Lock`), and the journal stops only on the exit of a linked process, not of a port.
- After losing its writer lock, a journal owner only closes its log: it no longer syncs, writes `summary.etf`, or releases a lock in a session directory another process may own by then.
- Session storage is private as documented: `session.dlog` was created `0644`, and `sessions/` and the project directories `0755`. Journals are now `0600` (`Tackle.Session.Reader.open_writable/2`), every directory from `sessions/` down to a session's is `0700` (`Tackle.Session.Storage.ensure_session_dir/2`), and `Storage.ensure_private_dir/1` makes the parents it creates private too. Journals and directories an earlier version created are tightened when the session is next opened for writing.
- Resuming a session that is moved to the archive or the trash at the same time no longer starts an empty session with its id. The journal checked that the session existed before taking its lock, and taking the lock recreated the moved directory and an empty journal. It now takes the lock with the new `Tackle.Session.Storage.acquire_existing_lock/2`, which creates no directory and checks the journal again under the lock, and fails with `{:session_not_found, session_id}`.
- The journal's child spec gives it its cleanup deadline (`journal_timeout`, 15 seconds by default, plus a second) as its shutdown time; the supervisor's default of five seconds could kill it while it was still closing the log, writing the summary, or releasing its lock.
- Crash reports and `:sys.get_status/1` no longer show conversation data. `format_status/1` of the journal (projection and creation options), its deadline process (queued requests and options; `Tackle.Session.Journal.Deadline`, renamed from `Journal.Watchdog` so it is not mistaken for the command watchdog `Tackle.Watchdog`), the catalog (cached search text and summaries in the last message), and the bash watchdog (tracked commands and output, the decision model's selection and options) reduces them to positions, operations, ids, and option keys.
- Journals keep loading after an event's version is bumped. Replay validated each event against its current version before upcasting it, so the upcast path was unreachable and the first version bump would have made every existing journal unreadable. The new `Tackle.Session.Log.read_commit/4` upcasts an older event one version at a time, through the upcasters the new `Log.schema/0` registers by `{type, from_version}`, and then validates it against the current version; versions from 1 up to the current one are read, newer ones stay unsupported, and event data must be a map. `Log.upcast_event/1` is gone; upcasting is private to `read_commit/4`.
- A malformed journal is reported instead of raised. Replay raised on event data it did not anticipate (a `message.appended` without its message, a compaction whose shadowed ids are `null`, metadata of the wrong type), so `Tackle.Session.Reader.read/2` raised, and a catalog rebuild or a text search, whose tasks are linked to the catalog and to the searching frontend, took those down too. The projection now checks event data and raises `Tackle.Session.ProjectionError` with a reason, the reader returns any exception from the fold as `{:error, {:invalid_projection, reason}}`, a compaction without shadowed ids (`nil`) shadows none, and the catalog skips a session it cannot index or search.
- A tool start whose result arrives in a later turn is no longer uncertain forever. A tool result resolved only the active turn's starts, so the results a repair turn writes for calls an earlier turn left open never resolved them, and `Tackle.inspect_session/2` kept listing them as uncertain. The projection keeps the session's pending tool starts (`Tackle.Session.Projection`'s `pending_tools`, each with the `turn_id` it started in) and resolves them by tool call id in any turn; turns no longer carry `pending_tools`. `Projection.uncertain_tools/1` is the one definition: the recovery a resumed session reports uses it too, where it listed only the interrupted turn's starts.
- A session's status no longer drifts from what replay reports. Only replay classified the projection, so a live owner kept the status it was opened with: a session stopped mid-turn was listed as `:active` in the running catalog and in its summary sidecar (replay said `:interrupted`), and one reopened with an interrupted turn stayed `:interrupted` after the turn was abandoned and later turns completed. `Tackle.Session.Projection` now classifies on every commit (`classify/1` is private; its status type is `:clean | :interrupted | :recovered`), the sidecar stores that status, and a stopping owner records it in the catalog, which lists `:active` only while the owner runs a turn. The journal keeps no copy of the active turn beside its projection's.
- `Tackle.Session.Spec`'s `storage` accepts only `:home`, `:env`, and `:journal_timeout`, which `Spec.new/1` checks (`{:unknown_storage_options, keys}`, `{:invalid_storage_option, key, value}`). It was an unchecked keyword list appended to the journal's options, so `path:` made the writer open another file than the journal of the directory whose lock it held, and `archived:`, `project_key:`, `force:`, or `reclaim:` reached storage internals. `Tackle.Session.Reader.open_writable/2` no longer honours `:path`; `read/2` still does.
- `Tackle.list_sessions/1` and `search_sessions/2` match a `:status` filter given as a string (`status: "active"`), which the filter type allowed but which matched no session; a string that names no status still matches none. `Tackle.Session.Catalog.Entry.status/0` types the statuses an entry can have (`:corrupt` and `:unsupported`, which nothing produced, are gone).
- A message whose usage names its provider with an atom (`Tackle.Lib.Usage` allows `provider: :openai`) is journaled with the provider's name as a string. The codec passed the atom through, so the journal refused the message as `{:forbidden_term, :atom, provider}` and the turn failed. Usage that is not plain data otherwise, such as a `raw` report holding a pid, is still refused.
- A catalog rebuild uses a session's summary sidecar without replaying the journal when the journal is unchanged. It compared the sidecar's sequence with `Tackle.Session.Reader.last_seq/2`, a full replay, so a valid sidecar never saved one and a stale one cost two, all within the two-second per-session timeout, after which the session vanished from listings. Sidecars now record the journal file's size and modification time (`summary.etf` keeps schema version 1; a sidecar without them, as earlier versions wrote, is replayed), a sidecar of a compressed journal is still trusted, and a replay that times out falls back to the session's sidecar as an entry marked `stale: true` (new `Tackle.Session.Catalog.Entry` field) instead of omitting the session. `Catalog.rebuild/1` also reports `stale`, `Catalog.sidecar/1` became `sidecar/2`, which takes the file's stat (`Catalog.journal_stat/1`), and `Reader.last_seq/2`, which looked cheap but replayed the whole journal and which only the catalog called, is removed.
- Catalog reads no longer exit the caller while the catalog rebuilds. The startup rebuild ran inside the catalog process, so with many sessions `Tackle.list_sessions/1`, `search_sessions/2`, and `session_summary/2` hit the default five-second call timeout, and the catalog recorded no journal updates meanwhile. `Tackle.Session.Catalog` now rebuilds in a task: it keeps recording journal updates and `forget/1`, which win over what the rebuild read, and `get/1`, `list/1`, `search/2`, and another `rebuild/1` wait, without a call timeout, until the running rebuild has finished, so a listing still never returns a partial index. The rebuild's own per-session timeouts bound the wait.
- Catalog entries are built one way, by `Tackle.Session.Catalog.Entry`: `from_projection/2` (with the listed `:status`, `:journal_path`, `:archived`, and optionally the search text), used by the journal, the catalog's rebuild, and `Tackle.Session.Store`; `to_sidecar/1` and `from_sidecar/1` for the summary that `summary.etf` stores; and `status_named/1`. `Tackle.Session.Catalog.record/1` takes an `Entry`, and `Catalog.encode_summary/1` and `decode_summary/1` are removed. Sidecars keep schema version 1 and no longer store the projection's model message and compaction counts, which nothing read; sidecars any earlier version wrote still load. Moving a session to or from the archive keeps its entry's `stale` mark.
- `Tackle.Session.Log` defines the events that settle a turn once, for the journal and the projection, and the new `Log.terminal_status/1` gives the status each gives its turn.
- `Tackle.Session.Reader` opens and names every `:disk_log` handle of a journal with one set of options: `Reader.name/1` is a session's writable log, and a fork writes its child with the new `Reader.write_journal/2`, so a fork's storage errors are the reader's `{:journal_open_failed, path, reason}`, `{:journal_append_failed, reason}`, and `{:journal_sync_failed, reason}`.
- The journal builds each event with a pure `Tackle.Session.Log` builder (`Log.turn_started/4`, `message_appended/2`, `tool_started/2`, `turn_settled/4`, and the others its module docs list) and validates a commit once before it appends it: each event's data must be durable plain data, which is what replay checks, and the commit must fold into the projection. A message was checked three times (by `Codec.encode_message/1`, per event by `Log.validate_commit/3`, and as part of the whole commit), so the depth and size limits now apply to the event data rather than the whole commit. `Log.validate_commit/3`, whose envelope and version checks held by construction for the commits the journal builds, is removed; stored commits are read with `Log.read_commit/4`.
- Whether a session is live in this node is answered by `Tackle.Session.Journal.whereis/1` alone, which no longer returns an owner that has exited. The new `Journal.ensure_not_live/1` (`{:error, :session_active}`) guards the store's moves and compression, and the new `Journal.current_projection/2` (the live owner's projection, else the file's) serves usage timelines and search, so a usage timeline whose owner stops while it is read returns `{:error, {:journal_unavailable, reason}}` instead of exiting.

#### Configuration and plugins (`packages/tackle`)

- `Tackle.Config.load/1` validates the `:context` override (a map whose `:executor`, if any, is an executor module and its config) before it reads anything. It read the project's `.tackle/config.json` through that executor first, so `{NotAModule, nil}` raised `UndefinedFunctionError` out of `load/1`, and a malformed executor fell back to the local one and read the project file unjailed before the load failed.
- `Tackle.Config.update/2` is the one way to change a built configuration and replaces `Config.reconfigure/2`: it changes `:model`, `:thinking`, `:max_iterations`, `:context` (merged), and `:llm_opts` (merged; the given options may not carry credentials, as in `new/1`) with `new/1`'s checks, including the context's executor, and rejects other keys with `{:unknown_update_options, keys}`. `Tackle.Runtime.RootBackend.configure/2` goes through it; it wrote the step limit, context, and adapter options straight into the struct, so a spec could be configured with credential options or a malformed executor, which tools take as the local one and run unjailed. `Tackle.Session.reconfigure/2` still changes only the model and thinking level and rejects other keys with `{:unknown_reconfigure_options, keys}`.
- `Tackle.Config.to_agent_state/2` raises `ArgumentError` for any option but `:session_id`. It ignored unknown options, so a caller still passing the removed `:credential_store` lost it silently.
- `Tackle.Config.SessionTitles`, `Watchdog`, and `Narration` share one skeleton (the private `Tackle.Config.Options`): `new/2` takes `nil`, `false`, or a keyword list, no longer a built struct; `enabled: false` turns the feature off without checking its other options (`SessionTitles` still resolved its model); and every invalid value is `{:error, {:invalid_option, name, detail}}`. `SessionTitles.new/2` raised `ArgumentError` out of `Tackle.Config.new/1` for a list that is not a keyword list.
- In `config.json` and `.tackle/config.json`, `true` and `false` mean `{"enabled": true}` and `{"enabled": false}` for every switchable feature (`session_titles`, `watchdog`, `narration`, `compile_gate`). `"watchdog": true` and `"narration": true` were errors while the other two accepted `true`, and a project file's `true` replaced the user's settings of the feature with the defaults instead of turning it on with them. The shape of a `session_titles` object is checked once, by `Tackle.Config.SessionTitles`, so a wrong `enabled` or `model` is an `{:invalid_option, :session_titles, detail}` error like the other features'.
- `Tackle.Config.Narration` (`interval_seconds`, `first_after_seconds`) and `Tackle.Config.Watchdog` (`after_seconds`) accept at most 4,294,967.295 seconds, the longest Erlang timer (`2^32 - 1` milliseconds). Any positive number passed, so `1e308` in `config.json` raised `ArithmeticError` when the narrator or watchdog converted it to milliseconds, and a larger integer made `Process.send_after/3` fail there, instead of the configuration being refused.
- `Tackle.Config.load/1` applies one precedence to every setting, overrides over environment over the project file over the user file over defaults, and validates only the winning value of an environment variable. A `thinking` from a file or `TACKLE_THINKING` replaced an explicit `overrides: [llm_opts: [reasoning_effort: ...]]`, and an invalid `TACKLE_THINKING` failed the load even when the overrides set `:thinking`. An override's `:thinking` still wins over its own `reasoning_effort`.
- `null` in `config.json` and `.tackle/config.json` leaves a field, or a member of an object, unset in that file, at any depth, so a project's `null` removes the user's value and the default applies, as the README stated. `"model": null`, `"thinking": null`, an `agents` entry such as `"scout": null`, `"jail": {"env": null}`, and a review stage's `null` were errors, and an object member's `null` reached the option's validation as a value. The CLI's sidebar preference treats `"show_subagent_sidebar": null` as unset (visible).
- Every error of a configuration file names the file as `{:config_file, path, reason}`, including invalid values such as `{:config_file, path, {:invalid_option, :watchdog, threshold: 1.5}}` or `{:config_file, path, {:unknown_model, ref}}`, which named neither the user nor the project file. The file's own errors are reasons of that shape too: `{:unreadable, posix}` (was `{:config_file_unreadable, path, posix}`), `:malformed` (`{:malformed_config_file, path}`), `:expected_object` (`{:invalid_config_file, path, :expected_object}`), `{:unknown_fields, fields}`, `{:invalid_field, field}`, `{:invalid_agent, name}`, and `{:invalid_provider, id}` (`{:unknown_config_fields, ...}`, `{:invalid_config_field, ...}`, `{:invalid_config_agent, ...}`, `{:invalid_config_provider, ...}`). When both files set an object, the user file is named if its value fails on its own, otherwise the project file; values from the environment or the overrides name no file. The CLI's sidebar preference reports its file errors in the same shape.
- `Tackle.Config` reports malformed option lists with one tag family per entry point: `load/1` with `{:invalid_loader_options, opts}`, `{:duplicate_loader_option, key}`, and `{:unknown_loader_options, keys}` (it mixed `{:invalid_config_loader_options, opts}`, `{:invalid_config, opts}`, and `{:duplicate_option, key}` with `{:unknown_loader_options, keys}`), `new/1` with `{:invalid_options, opts}` (was `{:invalid_config, opts}`), `{:duplicate_option, key}`, and `{:unknown_options, keys}`, and `update/2` with `{:invalid_update_options, opts}`, `{:duplicate_update_option, key}`, and `{:unknown_update_options, keys}`. Invalid option values are always `{:invalid_option, key, value}`: `load/1`'s `:overrides` and `:env` errors were the 2-tuples `{:invalid_option, :overrides}` and `{:invalid_option, :env}`, and `Tackle.Plugins` and `Tackle.Auth.Provider` reported an invalid `:accounts` or `:config_providers` as `{:invalid_plugin_option, key, value}`.
- `Tackle.Config` no longer has the `tool_policy`, `decision_model`, and `review` fields. `to_agent_state/2` sets the concurrent policy itself, and the decision model's reference and the review settings are read where sessions use them, `context.decisions.default_model` and `context.review_settings`; the fields were unused copies. The `:decision_model` and `:review` options of `new/1` are unchanged.
- `Tackle.Config.new/1` and `load/1` check tools without raising: a value that is not a tool module, a tool with missing callbacks, or one whose schema `Tackle.Lib.Tool.Registry.new/1` would refuse is `{:invalid_tool, tool, reason}` (`:not_a_module`, `{:missing_callbacks, callbacks}`, or `{:invalid_schema, :parameters | :output, message}`), where all were `{:invalid_tools, message}` with an exception's text. Hooks must implement a `Tackle.Lib.Hook` callback, as in the plugin catalog, or `{:invalid_hook, hook, :no_hook_callbacks}`; any loadable module was accepted as a hook (`{:invalid_module, :hooks, module}` otherwise) and then did nothing. `load/1` no longer builds the default system prompt that it replaces.
- `Tackle.Config.load/1` reads its sources and builds from them in two steps that hosts can call themselves: `Tackle.Config.Sources.read/1` takes `load/1`'s options and reads the environment, the working directory, `config.json` and the project file, the accounts, the skills, and the system prompt files, and `Tackle.Config.from_sources/2` builds a configuration from them without reading anything (`:overrides` merged over the sources' own, except `:providers` and `:context`, and `:instructions`, which can only leave instructions out). `Tackle.Coding.scope_spec/2` reads the sources once for the root and every subagent profile, where it called `load/1` for each of them plus once more, reading every file (the project file through the jail), the accounts, and the skills again and logging skipped skills again each time. With `instructions: false`, the scope's profiles get no instructions either; the root ignored the option. The prompt and skill assembly moved to the private `Tackle.Config.Prompt`, and `Tackle.SystemPrompt.build/1` is `read/1` (which keeps an unreadable file's error until a prompt uses it) followed by `compose/2`.
- `Tackle.Plugins.Catalog.new/1` rejects two adapters whose default providers share a provider id with `{:invalid_plugin, :adapter, source, {:duplicate_provider_id, id, first_adapter, second_adapter}}`. It only deduplicated adapter type ids, so such a pair passed the catalog and the CLI's startup check, and then every `Tackle.Config.load/1` and auth command failed with an unattributed `{:duplicate_provider_id, id}`.
- Providers must offer a model only once they are merged. `Tackle.Config.load/1` merges through `Tackle.Plugins.provider_entries/2`, which checks the merged providers for every adapter source. Without explicit adapters, `load/1` took them from the removed `Tackle.Plugins.available_adapters/1`, which required the adapters' default providers to offer one before the `config.json` providers were merged, so a host whose models are all declared in `config.json` (such as Ollama's) got `:no_models_configured`; with `:available_adapters` or `:catalog` no such check ran.
- Adapters are explicit everywhere; the `:tackle, :adapters` application environment is gone. `Tackle.Config.load/1` requires `:available_adapters` or `:catalog` (`{:error, {:missing_option, :available_adapters}}` without either), and `Tackle.Plugins.available_providers/2`, `provider_entries/2`, and `available_model_refs/2` and every `Tackle.Auth.Provider` function (`list/2`, `login/3`, `logout/3`, `status/3`, `usage/3`) take the adapter modules as their first argument instead of an `:adapters` option that defaulted to the application environment. `Tackle.Plugins.available_adapters/1`, `Tackle.load_config/1` (call `Tackle.Config.load/1`), and `Tackle.available_models/0` are removed. The CLI built its session catalog from its distribution while `tackle auth` read the application environment, which the CLI's removed `Tackle.CLI.Distribution.configure/0` set once per VM, so the two could disagree; the auth commands and the model lists now take the adapters of the session catalog (`Tackle.CLI.Distribution.adapters/0`).
- `Tackle.Plugins.Loader` compares a plugin's build of a dependency the host already runs by code, the built beam's `:beam_lib.md5/1` against the loaded module's `module_info(:md5)` (loading the module first if needed), instead of the file bytes at `:code.which/1`. In an escript the running beams live inside the archive, where that path names no readable file, so every shared module counted as a conflict and any plugin depending on `tackle_lib` was rejected with `:plugin_dependency_module_conflict`; beams stripped of debug information differed too. A build without the named application's `.app` file fails with `{:plugin_project_app_not_found, path, app}`, which was `{:plugin_project_app_not_found_or_ambiguous, app_files}` although it was never raised for an ambiguous application.

#### Credentials and accounts (`packages/tackle`)

- `Tackle.Auth.Store` no longer serves a copy of `auth.json` read at startup. Two VMs sharing the file (two CLIs, or a CLI and an SDK server) lost each other's updates, such as rotated Codex refresh tokens, other namespaces, and accounts, because every change wrote the whole map from memory, and they read stale credentials. Every change now re-reads and re-validates the file, applies its one change to those contents, and writes the result, and reads load the file again when its device, inode, size, or modification time differs from the last read or it was modified in the second that read began. Changes stay serialized within one store, with no lock across VMs. A file that becomes unreadable or invalid while the store runs makes reads and changes return `{:error, reason}` and is never overwritten. `Tackle.Auth.accounts/0` returns `{:ok, accounts} | {:error, reason}` instead of a bare map; `Tackle.Plugins`, `Tackle.Config.load/1`, and `Tackle.Auth.Provider` report a failure as `{:accounts_unavailable, reason}`.
- `Tackle.Auth.Store` names its temporary file `.auth.json.tmp-<OS pid>-<random>` with 12 bytes from `:crypto.strong_rand_bytes/1` and retries a name that exists, at most three times. The name came from a counter that restarts with every VM, so two VMs could pick the same name and a temporary file left by a killed VM made later saves fail with `{:auth_temporary_file_failed, path, :eexist}`. The harness application now lists `:crypto`.
- `Tackle.Auth.Store` implements `format_status/1` like the session processes: crash reports and `:sys.get_status/1` show the namespaces of the stored credentials but not the credentials, and the last message only as its operation. They showed every stored token.
- `Tackle.Auth.Provider` always passes adapters `Tackle.Auth.credential_store/0` as `:credential_store` and replaces a caller's. A caller could hand the adapter another store than the one the flows store logins in, read status from, and log out from.
- `Tackle.Auth.Provider.login/3` with `as: name` refuses a `name` that is the id of a default provider of any adapter with `{:default_provider_name, name}` before the adapter runs; the CLI explains it and suggests logging in without `--as`. `Tackle.Plugins` skips such an account, so a login with `--as` set to a default provider of the same adapter recorded an account that was never used. A default provider of another adapter was refused with `{:provider_adapter_conflict, name}`, which now covers only `config.json` providers and recorded accounts of another adapter. The `Tackle.Plugins` docs and the READMEs now state that the skip applies to any default provider's id.
- The harness's `mix tackle` task no longer runs its own DeepSeek login for `mix tackle auth login deepseek` from `packages/tackle`. That branch bypassed `Tackle.Auth.Provider.login/3`, named accounts, and the adapter's secret prompt, and echoed the API key through `Mix.shell().prompt/1`. Outside `apps/tackle_cli` the task passes every command to the CLI project's `mix tackle`; interactive logins run from `apps/tackle_cli` (`cd apps/tackle_cli && mix tackle auth login ID`), where the task calls the CLI in-process.
- `Tackle.Auth.Store` reports an unsupported `auth.json` version with the file's version, `{:unsupported_auth_version, path, file_version}`; it reported the supported version instead.

#### Other changes

- Renamed the pull request review app from `apps/tackle_web` (`:tackle_web`, `Tackle.Web.*`) to `apps/tackle_hub` (`:tackle_hub`), split the way Phoenix splits an app: the domain is `Tackle.Hub.*` in `lib/tackle_hub/` and the web layer (endpoint, router, plugs, controllers, LiveViews, components) is `Tackle.HubWeb.*` in `lib/tackle_hub_web/`. `Tackle.Web` had left no namespace for the web layer. Everything a deployment sees follows the new name: the release and its `bin/tackle_hub`, the `TACKLE_HUB_*` environment variables, the default database `tackle_hub` and database user `tackle-hub`, the session cookie `_tackle_hub` (signs everyone out), the Nix package `.#tackle-hub`, the NixOS module `nixosModules.tackle-hub` (`services.tackle-hub`, with service, user, `/var/lib/tackle-hub`, and `/var/lib/tackle-hub-home`), `tackle-hub-release`, and `nix/tackle-hub-deps.nix`. An existing deployment moves its database and state directory or sets the old ones explicitly, and finishes or discards queued Oban jobs first, since they name the old worker modules.
- The coding tools and their executors are their own package, `packages/tackle_tools` (`:tackle_tools`), on `tackle_lib` and `tackle_exec` only, so a host other than the harness can give its agents `read`, `bash`, `edit`, and `write`. `Tackle.Tools.Read`, `Bash` (with `Bash.Capture`), `Edit`, `Write`, `FileSystem`, `Output`, and `Tackle.Executor` with `Executor.Local` and `Executor.Jailed` moved with their tests and keep their names. The harness depends on it instead of `tackle_exec`; `Tackle.Tools.default/0` and the harness-specific tools stay. Woodpecker has a `tackle_tools` job, the pre-commit hook runs credo on it, and the Nix build includes it.
- Code review is its own package, `packages/tackle_review` (`:tackle_review`, `Tackle.Review.*`), on `tackle_lib`, `tackle_runtime`, `gix_ex`, and `yaml_frontmatter`, without harness code or storage (`docs/REVIEW_PACKAGE_PLAN.md`, phase 4). The harness depends on it instead of `gix_ex`. `Tackle.Tools.ReportFindings` and `ReportVerdict` are renamed `Tackle.Review.Tools.ReportFindings` and `ReportVerdict` (the tool names are unchanged), and `Tackle.Review.History` is renamed `Tackle.LocalReview.History` and stays in the harness with its file format. The package's tests run whole reviews on a test backend that runs `Tackle.Lib` loops without the harness. Woodpecker has a `tackle_review` job, and the Nix build includes the package.
- Code review's stage profiles, settings, and rule loading no longer depend on the harness (`docs/REVIEW_PACKAGE_PLAN.md`, phase 3). `Tackle.Review.Stages` holds the `review-detector` and `review-verifier` profiles as plain data, from which `Tackle.Agents.Default` builds its definitions (the `Tackle.Agents.Default.ReviewDetector` and `ReviewVerifier` modules are removed; the definitions are unchanged). `Tackle.Config.Review` is renamed `Tackle.Review.Settings` and gains `from_json/1`, which now parses `config.json`'s `review` object for `Tackle.Config.File`. `Tackle.Review.Rules.discover/1` moved to `Tackle.LocalReview.Rules.discover/1`; `Tackle.Review.Rules` instead loads rule files a host read (`load/2`, `project_dir/0`) and reads a repository's rules at a commit (`read_tree/3`), through the new `GixEx.read_dir/4`, which lists a directory's files at a revision from the object database. The `config.json` format and rule discovery behave as before.
- Code review is moving toward its own package (`docs/REVIEW_PACKAGE_PLAN.md`), so hosts without `TACKLE_HOME`, such as a database-backed review bot, can embed it. `Tackle.Review.run/2` no longer reads or writes anything itself: the `:history` and `:skip_outcomes` options are removed (known findings come in through `:known_fingerprints`), settings come in as `:settings` instead of the requester's session context, rules default to the built-in ones (new `Tackle.Review.Rules.builtin/1`) instead of being discovered from files, `:warnings` adds the host's warnings, and `result.summary` carries `rules` and `prompts` digests that `Tackle.Review.History.record_run/3` (no options now) records. The new `Tackle.LocalReview` supplies the local session's settings, rules discovered through the session executor, and the file history; the `review_changes` tool, `tackle review`, and the TUI `/review` use it, so their behaviour is unchanged.
- Code review no longer reads `Tackle.Config` to run its stages. `Tackle.Runtime.AgentBackend` gained optional `configure/2` (model, thinking level, step limit, session context, adapter options), `describe/1` (model, thinking level, step limit, system prompt, tool names), and `llm/1` (the model client with credentials, for direct calls) callbacks, exposed as `Tackle.Runtime.configure_spec/3`, `describe_spec/2`, and `spec_llm/2`, plus `Tackle.Runtime.prepare_spec/2`, which applies `prepare_child/2` without starting a run. `Tackle.Runtime.RootBackend` implements them; a review on a backend without them fails with `{:unsupported_agent_config, profile, reason}` before any run. `Tackle.Review.Delegation.put_review_context/3` now takes the requester, `Delegation.base_config/2` and `RootBackend.inherit_model/2` are removed, and `Tackle.Review.Detector.step_budget/1` takes a spec description.
- Moved `Tackle.Thinking` to `Tackle.Lib.Thinking` in `packages/tackle_lib`, so hosts and packages above the library share it. Callers must use the new name.
- Moved the Markdown front matter parser `Tackle.Skills.Frontmatter` into its own dependency-free package, `packages/yaml_frontmatter` (`YamlFrontmatter`, now documented, with its tests), so neither `tackle_lib` nor code review depends on skills code. The harness uses it for skills, agent definitions, and review rules.
- `review_changes` no longer drops verified findings silently. Findings the verifier confirmed (or left uncertain) that the review profile's confidence thresholds or cap keep out of the result (`Tackle.Review.Result.hidden/1`, new) are now listed after the shown findings in a `Verified but not shown under the <profile> profile:` section, each with its reason and trigger (at most ten, the rest counted). Previously only the blocking and optional lists were returned, so the agent never saw findings the CLI's progress had marked confirmed. Scoring failures are now noted too. The CLI's `review_changes` card counts the hidden findings and no longer shows a review with only hidden findings as clean, and the `/review` overlay notes them.
- Renamed the workflow engine package from `packages/tackle_script` to `packages/tackle_workflow`, and its identity from `:tackle_script`/`Tackle.Script.*` to `:tackle_workflow`/`Tackle.Workflow.*` (`Tackle.Workflow.Ref`, `.Server`, `.Application`, `.Registry`, `.Supervisor`, `.Fanout`, `.API`, `.Tool`). The model-facing tool is now `run_workflow` (it was `run_script`) and the host context key is `:workflow_profiles` (it was `:script_profiles`). Lifecycle reasons moved from `:script_*` to `:workflow_*`, including `{:workflow_compile_error, message}` and `{:workflow_crashed, message}`. The Lua surface the workflow itself writes is unchanged (`tackle.spawn/2`, `tackle.await/1`, `tackle.parallel/3`, `tackle.cancel/2`, `tackle.log/1`), as is the `script` argument that carries Lua source. This is breaking for anyone who depended on the package, module, or tool names: the harness only used it as a test-only dependency.
- Review runs no longer spend a model call on a closing answer. A detector run is stopped as soon as its last `report_findings` call recorded every finding it carried (`Tackle.Tools.ReportFindings.complete?/2`), and a verifier run once every finding has its verdict; in traced reviews that closing call took 3 to 9 seconds per run, on the critical path for the last detector and its verifier. `Tackle.Review.Delegation.run/4` gained a `:done?` option that checks the run's transcript after each tool result and stops the run (`Tackle.Runtime.cancel_run/3`) once it holds, returning `{:ok, state}`. Such runs appear as cancelled among the scope's tasks.
- A failed delegated run no longer costs a review the findings it already made. Review detectors now report findings as they confirm them (`report_findings` takes `done: false` while a run keeps reviewing), and whatever a detector or verifier run reported before an agent error, the step limit, a timeout, a crash, or its own cancellation is kept: `Tackle.Review.Delegation` mirrors a run's finished messages from its events, so a timed-out run's transcript is no longer lost. Units whose runs stopped early after reporting are listed in the new `Result.summary.incomplete_units` (also in the tool result, the CLI's text and JSON output, the TUI's notes, and review history); `failed_units` now holds only units whose runs reported nothing. A delegated run cancelled on its own is a failed run (`:run_cancelled`) instead of cancelling the whole review; cancelling the requester's branch or scope still cancels it. `Delegation.run/4` now returns `{:error, reason, messages}` for every run that started and failed, and `ReportFindings.reported?/2` became `finished?/2`.
